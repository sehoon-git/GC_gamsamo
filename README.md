# 상담 커피톡 · GC_gamsamo

2026 게임인재원 AI 해커톤 팀 공용 저장소입니다.

작업 루틴은 **풀 → 요청한 작업 확인 → 작업 → PR**입니다. 최신 변경을 풀한 뒤 [저장소 작업 지침](AGENTS.md)과 [통합 기획서 plan01](docs/plan01.md)을 읽고 요청 범위를 확인합니다. 작업 중 생긴 변경사항은 반드시 plan01의 기준·구현 상태와 [작업 이력](docs/plan01.md#work-history)에 반영합니다. 완료 시각·함수·규칙·검증·다음 작업을 기록하고 코드와 문서를 PR 하나로 제출하며, 후속 수정도 같은 PR에 포함합니다. `main` 직접 푸시·PR 병합·자동 병합 설정은 하지 않습니다. 병합 판단과 실행은 사용자가 맡습니다.

현재 프로젝트에는 **상담실·환자 6명 입장과 임시 대화·진료기록부·PC·상점·프로필·사진·환경설정 UI**가 구현되어 있습니다. 문을 클릭하면 한 명씩 입장해 책상 뒤 중앙에 앉고 이름이 있는 대화창에서 임시 대사를 표시합니다. 상담 종료를 확인하기 전에는 다음 환자를 받을 수 없습니다. 왼쪽 아래 기록부는 입장한 환자의 이름·ID를, 모니터는 PC 바탕화면을 중앙에 표시합니다. 상점은 5개 분류마다 8종씩 총 40종의 치장을 미리보기로 적용하며 창문 블라인드를 조절할 수 있습니다. 대화 서버·평가·게임 진행 저장·실제 재화와 구매 기능은 아직 연결하지 않았습니다.

시작 화면과 설정 화면의 배치·클릭 시안은 [시작 화면 미리보기](tools/ui-preview/start-menu/index.html)를 브라우저에서 열어 확인할 수 있습니다. `새 게임 / 불러오기 / 설정 / 게임 종료` 네 메뉴와 한 페이지의 상단 그래픽·하단 오디오 구성을 담았습니다. 실제 자동 저장이 연결되지 않아 불러오기는 비활성화되어 있습니다. Unity 시작 씬·실제 설정 적용·저장·앱 종료 기능과는 구분하며, 상세 동작과 연결 범위는 [plan01](docs/plan01.md)의 8.4절·15절에 있습니다.

최신 기획은 **환자가 먼저 말하고 → 플레이어가 서술형으로 답하고 → 대화를 이어가며 정보를 얻고 → 사용자가 `상담 마치기`로 종료**하는 방식입니다. 질문·답변 횟수 제한과 횟수 소진에 따른 자동 종료는 없습니다. [plan01](docs/plan01.md) v0.11은 게임과 AI의 차이를 16개 항목으로 점검하고 구현 상태와 남은 검증을 구분합니다.

**서윤 1인 AI 베타는 게임의 대화 방식에 맞춘 API·저장 형식 4입니다.** `/start`로 환자가 먼저 말하며, 여러 문장·공감·복수 질문을 그대로 보낼 수 있습니다. 질문 분류·횟수 계산·강제 분리를 제거했습니다. 사용자 종료 요청 → 고정 상담자 안내 저장 → 두 축 평가 순서이며 종료 안내는 “상담은 여기까지 하겠습니다. 오늘 수고하셨습니다!”입니다. 이 안내는 환자 발언이나 평가 근거가 아닙니다. 이전 형식 1~3 기록은 보존하며 자동 변환하지 않습니다. [공용 API·모의 응답](contracts/README.md)을 기준으로 연결하고, Unity 실제 통합 및 실제 모델의 한국어 품질은 별도로 검증합니다. 도현·민석·태준·지은·하린의 AI 설정·평가 원본은 아직 없어 서윤 데이터로 대체하지 않습니다.

## 서윤 AI 베타 실행

설치와 모델 다운로드 후 저장소 루트에서 실행합니다.

```bash
conda activate game-ai
python tools/run_experiment.py --server-only
# 별도 터미널
python tools/chat.py
```

서버 전용 모드에서는 CLI의 `x`로 대화만 종료하며 서버는 유지됩니다. GPU 없는 연결은 `python tools/run_experiment.py --mock --server-only`로 시작합니다. [AI 실행 안내](ai/README.md), [환경변수·A6000 이전 안내](ai/environment.md), [진행 상황·검증·기획과의 차이](ai/progress.md), [현재 실험 API](contracts/README.md)를 참고하세요.

## 상담실 UI 실행

1. `ProjectSettings/ProjectVersion.txt`에 기록된 Unity `6000.3.28f1`로 프로젝트를 엽니다.
2. `Assets/_Project/Scenes/ConsultationRoom.unity`를 열고 Play를 누릅니다.
3. 왼쪽 문을 클릭하면 **서윤 → 도현 → 민석 → 태준 → 지은 → 하린** 순서로 한 명씩 입장합니다. 입장·상담·퇴장 중에는 문을 다시 눌러도 다른 환자가 들어오지 않습니다.
4. 환자가 자리에 도착하면 이름과 임시 대사가 자동으로 표시됩니다. `계속 듣기`는 타이핑 중인 문장을 바로 표시하거나 다음 임시 대사로 넘깁니다. `상담 마치기` → 확인을 누르면 퇴장하고, 문을 눌러 다음 환자를 받을 수 있습니다. 6명 이후에는 입장이 끝납니다.
5. 책상 왼쪽 아래 기록부를 클릭합니다. 입장한 환자의 이름·ID가 표시되며 나머지 임상 정보는 아직 확인하지 않은 상태입니다. 닫기 버튼, `Esc`, 기록부 바깥 배경 클릭으로 닫을 수 있습니다.
6. 오른쪽 모니터를 클릭하면 중앙에 PC 바탕화면이 열립니다. `상점` 아이콘으로 창문·문·서류철·PC·PC 배경화면 탭을 선택하고 각 탭의 카드 8개를 클릭해 외형을 미리 봅니다. `기본 복원`은 현재 분류만 되돌립니다. 창문 치장을 선택하면 `올림 / 절반 / 내림`으로 블라인드를 바꿀 수 있습니다.
7. 상점의 X 또는 `Esc`는 바탕화면으로 돌아갑니다. PC의 X는 전체 PC를 닫습니다. 바탕화면에서 `Esc` 또는 바깥 클릭으로 상담실에 돌아갑니다. 내부 창이 열려 있을 때 바깥 클릭은 그 창부터 닫습니다.

환자 순서와 대사는 로컬 화면 확인용이며 정식 환자 해금·평가·상담 완료 규칙이 아닙니다. PC나 기록부를 열면 대화창과 타이핑·입퇴장 연출이 잠시 멈추고 닫은 뒤 이어집니다. 이번 입장 순서와 대화는 Play를 다시 시작하면 초기화되며 Python 서버 없이 실행됩니다. LLM 연결은 `PatientVisitController.PatientArrived(sessionId, patientId)`와 `PresentPatientLine(sessionId, text)`로 교체할 수 있습니다. 긴 응답의 페이지 나누기, 서술형 답변 입력·전송, 사용자 종료와 서버 연결, 평가·보상·저장은 후속 작업입니다.

환자 UI를 기존 씬에 추가하는 메뉴는 Edit 모드의 `Gamsamo > Install Patient Visits`입니다. 상담실 씬을 저장하고 해당 프리팹 편집 모드를 닫은 뒤 실행하면 기존 방·PC·치장을 보존하면서 씬과 프리팹을 함께 갱신합니다. 검사는 새 Play 실행의 대기 상태에서 `Gamsamo > Run Patient Visit Checks`를 사용합니다. 결과는 Git 제외 영역 `artifacts/ui/patient-visit-checks.txt`에 남습니다.

내 프로필은 남녀 아바타와 이름·소속·소개를 표시하고, 사진은 6개 슬롯을 제공합니다. 실제 프로필 정보·사진이 없으면 빈 상태입니다. 환경설정은 해상도·화면 모드와 전체/BGM/효과음 값을 편집하며 **적용으로 저장, 닫기·Esc로 미적용 변경 취소**합니다. 화면 변경은 실행 빌드에서 적용하고 Editor에서는 바꾸지 않습니다. 음원은 아직 없습니다.

상점은 `미리보기 · 가격 미정`과 잔액 `— C`를 표시합니다. 새 원본 카탈로그의 40종 가격은 모두 `null`이며 무료·0원으로 해석하지 않습니다. 원본 통화 `KRW`는 보존하고 UI만 기존 게임 단위 C로 표시하며, 환산이나 지갑 연결은 없습니다. 치장 선택은 PC를 닫아도 같은 Play 실행 동안 유지되고, Play 종료 후 다음 실행에서는 기본 외형으로 시작합니다. 소유권·재화·게임 저장은 변경하지 않습니다. 서류철은 책상 위 모습과 확대 기록부를 함께 바꾸며 기록 내용·빈 사진 칸은 유지합니다.

PC 창은 실제 상담실 배경 너비의 82% 안에서 비율을 유지합니다. 넓은 게임 뷰에 여백이 생겨도 PC와 상점이 상담실 화면 밖으로 커지지 않습니다.

UI 프리팹은 `Assets/_Project/Prefabs/ConsultationRoomUI.prefab`입니다. 첫 입장 전 기록은 `ConsultationRoomController`의 `record` 예시이고, 입장하면 `PatientVisitController`가 `SetRecord(MedicalRecordData)`로 현재 환자의 이름·ID·방문 날짜와 미확인 항목을 전달합니다. 환자 원본 설정이나 LLM 공개 정보는 아직 변환하지 않습니다. 기록부 사진 칸은 항상 공백입니다. 배경과 팝업은 화면 비율을 유지하며, 화면 비율이 다르면 상담실 좌우 또는 상하에 여백이 생깁니다.

Play 모드에서 `Gamsamo > Run UI Smoke Checks`로 클릭 영역, 모달 차단, 블러, 한글 표시, 텍스트 넘침, 닫기와 재열기를 검사합니다. 결과와 화면 캡처는 Git에서 제외된 `artifacts/ui/`에 저장됩니다. 씬을 처음 생성하는 도구는 `Gamsamo > Create Consultation Room Scene`이며, 기존 씬이 있으면 덮어쓰지 않습니다.

치장 40종과 블라인드·날씨 조합은 Play 모드의 `Gamsamo > Run Cosmetic Checks`로 검사합니다. 결과는 `artifacts/ui/cosmetic-checks.txt`에 남고 해당 폴더는 커밋하지 않습니다. PC 검사는 Play 모드의 `Gamsamo > Run PC UI Smoke Checks`로 실행합니다. 새 레이어·날씨·치장 연결은 `Gamsamo > Run Room Appearance Checks`로 검사합니다. PC·상점은 저장된 씬과 프리팹에 이미 연결되어 있습니다. 기존 기록부 씬에 PC를 추가하는 도구는 `Gamsamo > Install PC Desktop UI`이며, 이미 설치된 UI를 다시 만들지 않습니다. 실행 전 해당 씬을 저장하고 상담실 프리팹 편집 모드를 닫아야 합니다.

새 에셋 갱신 메뉴는 Edit 모드의 `Gamsamo > Apply Counseling Asset Pack`입니다. 저장된 씬과 프리팹 양쪽을 갱신하며, 프로필·사진·설정 창과 동적 상점 카드를 중복 생성하지 않습니다. `CosmeticCatalogImporter.Build()`가 원본 카탈로그·가격 미정·블라인드 구성·상대 경로를 검증하고 `Assets/_Project/Settings/CosmeticCatalog.asset`을 생성·갱신합니다. `CosmeticShopBuilder.Build(...)`는 빈 탭 템플릿 위에 썸네일·이름·선택 표시를 구성합니다.

미리보기 진입점은 `CosmeticAppearanceController.Preview(id)`이며 `RestoreCategory(target)`·`RestoreAll()`로 되돌립니다. 창문은 `ConsultationRoomAppearance.SetWindowVariant`로 테마별 블라인드 3단계×날씨 3종을 연결하고 `SetWeather`로 현재 날씨를 바꿉니다. 첫 창문 선택은 절반 상태이며 다른 테마와 날씨를 선택해도 현재 블라인드 단계는 유지합니다. 완성된 상태 이미지 위에 블라인드 오버레이를 다시 겹치지 않습니다. `PcDesktopView.TryApplyCosmetic`의 외형 교체 연결도 유지하며 소유권·결제 검증은 하지 않습니다. 자동 날씨 결정과 구매 로직은 후속 작업입니다.

### 화면 에셋과 폰트

- 환자: `Assets/_Project/Art/Characters/Patients/`의 6개 초상화와 `Assets/_Project/Settings/PatientVisits.json`의 이름·순서·임시 대사를 연결합니다. 초상화의 어두운 바탕은 전용 셰이더로 표시에서 제거하고 책상 경계에서 마스킹합니다. 이는 정식 환자 설정 JSON과 별개인 화면 시연 자료입니다.
- 대화창: `Assets/_Project/Art/UI/Dialogue/DialoguePanel.png` — 기본 제공 ImageGen으로 생성한 2172×724 투명 배경의 따뜻한 종이색 패널입니다. 인물 이름·대사는 이미지에 새기지 않고 TextMeshPro로 표시합니다. [생성 프롬프트와 사용 규칙](docs/plan01.md#patient-dialogue-art)을 통합 기획서에 보관합니다.

- 기록부: `CounselingPack/room/medical-record-front.png` — 새 팩의 투명 외곽·빈 사진 칸 이미지를 사용합니다. 이전 `MedicalRecord.png`와 편집 기록은 보존합니다.
- PC·내부 창: `Assets/_Project/Art/UI/PcDesktop/`, `CounselingPack/profile/`, `photos/`, `settings/` — 이전 적용에서 기존 PC·상점 PNG 12개를 재사용하고 `pc-frame.png` 등 PNG 15개를 추가했습니다. 완성 배경·overview·preview·pc-open은 참고용으로 보존합니다.
- 치장: `Assets/_Project/Art/UI/CounselingPack/cosmetics/` — 원본 PNG 202개·JSON 2개·TXT 안내 2개로 총 206개 파일을 포함합니다. 원본 `catalog.json`과 `window/blind-states.json`을 기준으로 5분류×8테마를 연결합니다. 안내 문서는 참고자료이며 게임 규칙을 덮어쓰지 않습니다.
- 동적 상점: `Assets/_Project/Art/UI/CosmeticShop/templates/`의 빈 탭 PNG 5개를 사용합니다. 이번 신규 PNG는 치장 원본 202개와 템플릿 5개를 합한 207개입니다. 기존 `tabs/`의 완성 카드 PNG 5개와 `layout.json`도 새 제공본으로 갱신하되, 실제 UI는 템플릿과 개별 카드 데이터로 구성합니다. 레이아웃의 카탈로그 경로는 프로젝트 배치에 맞춘 `../CounselingPack/cosmetics/catalog.json`입니다.
- 기록부 편집에는 기본 제공 ImageGen을 사용했습니다. 편집 지시는 원본의 1024 × 1536 구도, 클립보드·종이 질감, 한글 제목·항목명·표 선을 유지하면서 외곽과 클립 구멍만 투명하게 만들고, 사진 속 인물만 제거해 테두리 안을 종이색 공백으로 채우는 내용입니다. [최종 편집 프롬프트](docs/plan01.md#asset-edit)는 통합 기획서에 보관합니다.
- 한글은 [Noto Sans CJK KR](https://github.com/notofonts/noto-cjk/tree/main/Sans/OTF/Korean)의 프로젝트 포함 폰트를 사용합니다. 라이선스는 `Assets/_Project/Fonts/OFL.txt`에 있습니다. TextMeshPro 필수 리소스는 `Assets/TextMesh Pro/`에 포함되어 있습니다.

서윤 실험의 모델과 서버 구성은 위와 같이 확정했습니다. 모델 설정·서빙 연동·품질 및 속도 검증 결과는 `ai/`와 `server/`에 기록합니다.

- **Unity:** 환자 발화 표시·서술형 입력·전송·상담 마치기, 진행도, 정보 공개 확정, 점수 기반 보상·치장 구매·장착, 승급, 엔딩과 자동 저장 연동을 담당합니다.
- **대화 서버:** 환자 설정·기억에 따른 첫 발화와 자유 서술형 응답, 사용자 종료·고정 안내·평가를 처리합니다. 첫 발화는 별도 `opening`으로 보존하고 가짜 상담자 발언을 만들지 않습니다. 클라이언트가 종료 원문 저장에 성공한 이후 두 축 평가를 호출합니다.
- **추론 엔진:** 모델을 실행합니다. 모델·서빙 도구가 바뀌어도 게임의 API 규격을 유지하도록 연결부를 분리합니다.
- **공용 데이터:** 환자 JSON 원본은 `Assets/StreamingAssets/GameData/Patients/` 한 곳에서 관리합니다. API·데이터 규격은 프론트와 백엔드가 `contracts/`에서 맞춥니다.

## 협업 기준

1. Unity 담당자가 프로젝트 버전과 렌더러를 관리하고 기본 설정을 공유합니다. 현재 버전은 `ProjectSettings/ProjectVersion.txt`를 기준으로 하며, uGUI와 TextMeshPro를 사용합니다.
2. 환자 데이터 형식과 대화 API 요청·응답 규격을 먼저 합의한 뒤 각자 구현합니다.
3. Unity 에셋과 연결된 `.meta`는 함께 커밋합니다. 씬을 동시에 수정하기보다 담당자를 정하고 프리팹·스크립트·데이터로 작업을 나눕니다.
4. 모델 가중치, 빌드, 캐시, 가상환경과 실제 접근 키는 Git에 넣지 않습니다. Unity가 추후 생성하는 `.meta`와 패키지 잠금 파일은 공유합니다.
5. 상담 기록과 사용자 설정은 실행 환경의 로컬 저장 공간에 보관하도록 구현합니다.
