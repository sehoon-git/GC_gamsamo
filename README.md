# 우리동네 상담사 · GC_gamsamo

2026 게임인재원 AI 해커톤 팀 공용 저장소입니다.

작업 루틴은 **풀 → 요청한 작업 확인 → 작업 → PR**입니다. 최신 변경을 풀한 뒤 [저장소 작업 지침](AGENTS.md)과 [통합 기획서 plan01](docs/plan01.md)을 읽고 요청 범위를 확인합니다. 작업 중 생긴 변경사항은 반드시 plan01의 기준·구현 상태와 [작업 이력](docs/plan01.md#work-history)에 반영합니다. 완료 시각·함수·규칙·검증·다음 작업을 기록하고 코드와 문서를 PR 하나로 제출하며, 후속 수정도 같은 PR에 포함합니다. `main` 직접 푸시·PR 병합·자동 병합 설정은 하지 않습니다. 병합 판단과 실행은 사용자가 맡습니다.

현재 프로젝트에는 **시작 화면·상담실·환자 6명 입장·5명의 서술형 입력과 외부 AI 연결·진료기록부·PC·상점·프로필·사진·환경설정 UI**가 있습니다. 문을 클릭하면 한 명씩 입장하며 진행 중인 환자가 퇴장하기 전에는 다른 환자를 받을 수 없습니다. AI 지원 환자는 [PR #24](https://github.com/sehoon-git/GC_gamsamo/pull/24)의 `PatientAiAdapter`에 기존 입력창을 연결하고, 상담 원문과 저장된 평가를 책상 서류에서 열람합니다. 서윤·도현·태준·연우·하린을 지원하며 민석은 입력창 없는 로컬 시연입니다. 상점 48종은 외형 미리보기이며 정식 해금·승급·게임 전체 진행 저장·재화·구매·엔딩은 별도 작업입니다. 최신 구현·실행 검증 상태는 [plan01 작업 기록](docs/plan01.md#work-history)을 따릅니다.

시작 화면과 설정 화면의 배치·클릭 시안은 [시작 화면 미리보기](tools/ui-preview/start-menu/index.html)를 브라우저에서 열어 확인할 수 있습니다. `새 게임 / 불러오기 / 설정 / 게임 종료` 네 메뉴와 한 페이지의 상단 그래픽·하단 오디오 구성을 담았습니다. 게임 전체 진행 저장이 연결되지 않아 불러오기는 비활성화되어 있습니다. Unity 시작 화면은 별도로 구현되어 있으며, 상세 동작과 연결 범위는 [plan01](docs/plan01.md)의 8.4절·15절에 있습니다.

최신 기획은 **환자가 먼저 말하고 → 플레이어가 서술형으로 답하고 → 대화를 이어가며 정보를 얻고 → 원할 때 `상담 그만하기`로 종료**하는 방식입니다. 주질문·후속질문 구분과 횟수 제한은 없습니다. 문 옆 `상담 중 1/6` 박스는 제거하고 처리 상태는 말풍선 안에서 안내합니다. 평가 결과는 책상 서류에 원문과 함께 보관합니다. 종료·평가 저장 후에도 환자는 자리에 머물며, 사용자가 `환자 내보내기`를 눌러야 퇴장합니다. [plan01](docs/plan01.md) v0.16에서 현재 연결과 남은 검증을 구분합니다.

**5인 AI 베타는 API·저장 형식 4입니다.** `/start`의 환자 선발화 이후 공감·제안·복수 질문을 그대로 보낼 수 있습니다. 사용자 종료 요청 → 고정 상담자 안내 저장 → 두 축 평가 순서이며 안내는 “상담은 여기까지 하겠습니다. 오늘 수고하셨습니다!”입니다. 이 안내는 환자 발언이나 평가 근거가 아닙니다. 이전 형식 1~3 기록은 보존하며 자동 변환하지 않습니다. PR #24의 실제 모델·공개 HTTPS 검증 기록은 보존하지만 이번 입력 UI·서류 표시를 포함한 실제 서버 Unity 조작 검증과는 구분합니다. 각 환자의 공개 정보·기억·평가·저장을 분리합니다. 지은의 표시 이름과 ID는 연우(`yeonwoo`)로 교체하고 초상화 참조는 유지합니다.

PR #28·#29의 AI 검증 결과는 당시 이력으로 보존합니다. 완료된 사례를 다음 Play에서 복원해도 자동 퇴장하거나 새 상담을 시작하지 않습니다. 마지막 환자 대사와 저장된 원문·평가를 확인한 뒤 `환자 내보내기`로 방문을 마칩니다. 재상담·새 실험 선택 UI와 게임 전체 저장은 아직 없으며 기록부 목록은 해당 환자 입장 시 저장된 기록으로 다시 구성됩니다. 이번 수정은 C# 컴파일과 입력 브리지 검사 56개, 실제 Unity 조작의 복원 환자 체류·문 차단·기록부 열기/닫기·명시적 퇴장·다음 환자 입장·이전 평가 보존을 확인했습니다. Console 오류·경고는 0개이며 새 대화부터 평가까지의 추가 전체 검증은 사용자 요청으로 생략했습니다.

PR #30의 통합은 `main`의 AI·입력·상담 기록과 `feature/ui`의 시작 화면·48종 치장·기록부 드래그·해상도 설정을 합칩니다. 해당 PR에 기재된 전체 서버 검증은 통합 전 main의 결과입니다. 당시 병합은 Runtime/Editor 컴파일·씬/프리팹 참조·시작 메뉴 23개 검사와 실제 Play의 PC/상점·벽지 탭·서류 열기·서윤 AI 첫 발화/입력창을 확인했습니다. 상점 글꼴 경고를 수정한 뒤 재실행의 Console 오류·경고는 0개였습니다. 상세 필수 검사 결과는 [plan01 17.27](docs/plan01.md#work-history)에 별도로 기록합니다.

## AI 베타 실행

설치와 모델 다운로드 후 저장소 루트에서 실행합니다.

```bash
conda activate game-ai
python tools/run_experiment.py --server-only
# 별도 터미널
python tools/chat.py --patient seoyun
# 다른 환자: dohyeon, taejun, yeonwoo, harin
```

서버 전용 모드에서는 CLI의 `x`로 대화만 종료하며 서버는 유지됩니다. 현재 게임은 담당자가 준비한 외부 서버에 연결합니다. 이번 UI 작업용 임시 모의 서버와 접속 설정은 사용하지 않습니다. 저장소의 모의 API·합성 계약 자료는 개발 검사용으로 구분합니다. [AI 실행 안내](ai/README.md), [환경변수·A6000 이전 안내](ai/environment.md), [진행 상황](ai/progress.md), [현재 API 계약](contracts/README.md)을 참고하세요.

## Unity AI 연결 준비

`Gamsamo > AI > Import Connection JSON`에서 별도로 전달받은 `api_url`, `api_key` 설정을 가져옵니다. 기본 파일은 프로젝트 밖의 `Application.persistentDataPath/ai-connection.json`입니다. `GAMSAMO_AI_CONNECTION`으로 다른 파일을 지정할 수 있으며 파일이 없으면 `SEOYUN_API_URL`·`SEOYUN_API_KEY`를 읽습니다. 원격 서버는 HTTPS와 접근 키가 필요합니다. 주소·키를 씬·프리팹·저장소에 넣지 않습니다. 이전 임시 `UserSettings/CounselingApi.json`과 독립 `ConsultationApiClient`는 현재 연결에 사용하지 않습니다.

`ConsultationRoom.unity`를 열어 `Gamsamo > AI > Validate Current Scene`을 실행하고 Play를 시작하면 지원 환자별 AI 어댑터가 자동 연결됩니다. `PatientAiInputBridge`는 기존 입력창을 `SubmitText(string)`·`UpdateDraft(string)`와 상태 이벤트에 연결합니다. Enter는 줄바꿈이며 `Ctrl+Enter` 또는 `전송`으로 보냅니다. 한글 조합 중에는 전송하지 않습니다. [연결 명세](contracts/README.md#unity-text-input)에 초안·재시도·종료·서류 표시 규칙을 정리했습니다. 서버 설정이 없거나 연결되지 않으면 오류를 표시하고 기존 원문을 보존합니다.

## 상담실 UI 실행

1. `ProjectSettings/ProjectVersion.txt`에 기록된 Unity `6000.3.28f1`로 프로젝트를 엽니다.
2. `Assets/_Project/Scenes/StartMenu.unity`를 열고 Play → `상담실 입장`으로 상담실에 들어갑니다. 빌드의 첫 씬도 StartMenu입니다. 상담실만 편집할 때는 `ConsultationRoom.unity`를 직접 열 수 있습니다.
3. 왼쪽 문을 클릭하면 **서윤 → 도현 → 민석 → 태준 → 연우 → 하린** 순서로 한 명씩 입장합니다. 입장·상담·퇴장 대기·퇴장 중에는 문을 다시 눌러도 다른 환자가 들어오지 않습니다.
4. 서윤·도현·태준·연우·하린은 각자의 첫 이야기를 읽고 입력창에 답변을 작성해 전송합니다. 빈 입력창의 자리표시자와 입력 대기 안내 문구는 표시하지 않습니다. 주질문·후속질문·왕복 수 제한 없이 대화하고 `상담 그만하기` → 확인으로 종료합니다. 취소하면 계속 상담합니다. 진행 중 요청·원문·고정 안내·평가가 저장되면 `환자 내보내기` 버튼이 나타납니다. 기록부를 열고 닫아도 환자는 머무르며 버튼을 직접 눌러야 퇴장합니다. 민석만 입력창 없는 로컬 시연이며 종료 확인 뒤 같은 버튼으로 내보냅니다.
5. 책상 왼쪽 아래 서류를 클릭해 `상담 메모 / 대화 원문 / 상담 결과` 탭을 선택합니다. `이전 쪽 / 다음 쪽`으로 긴 내용을 읽고 `이전 서류 / 다음 서류`로 이번 실행에서 보관한 환자 기록을 고릅니다. 평가 점수·항목별 이유·근거는 저장된 결과를 사용합니다. 별도의 평가 결과 대화창은 띄우지 않습니다. 제공되지 않은 신상·병력·복약은 미확인 상태로 남깁니다. 펼친 서류는 화면 안에서 드래그할 수 있으며 `Esc` 또는 바깥 클릭으로 닫고 다시 열면 중앙에 표시합니다. X 버튼은 숨깁니다.
6. 오른쪽 모니터를 클릭하면 중앙에 PC 바탕화면이 열립니다. `상점` 아이콘으로 창문·문·서류철·PC·PC 배경화면·벽지 탭을 선택하고 각 탭의 카드 8개를 클릭해 외형을 미리 봅니다. `기본 복원`은 현재 분류만 되돌립니다. 창문 디자인을 선택한 뒤 PC를 닫고 상담실 창문을 클릭하면 블라인드가 올림 → 절반 → 내림 순서로 바뀝니다. 기본 창문은 블라인드가 없습니다.
7. 상점의 X 또는 `Esc`는 바탕화면으로 돌아갑니다. PC의 X는 전체 PC를 닫습니다. 바탕화면에서 `Esc` 또는 바깥 클릭으로 상담실에 돌아갑니다. 내부 창이 열려 있을 때 바깥 클릭은 그 창부터 닫습니다.

고정 방문 순서는 화면 시연용이며 정식 해금·클리어 수가 아닙니다. PC나 기록부를 열면 대화창·타이핑·입퇴장 연출을 잠시 멈추며 확정 결과와 초안을 보존합니다. Play를 다시 시작하면 방문 순서는 초기화되지만 지원 5명의 AI 상담은 각각 `Application.persistentDataPath/ai-saves/<patient_id>/`에서 복원됩니다. 저장 완료 사례도 착석 후 내보내기를 기다리고 새 회차를 자동 생성하지 않습니다. `AiSession`이 요청·초안·종료 의도를, `AiSaveStore`가 전체 상태와 원문 저장을 담당합니다. 통신 실패는 같은 요청을 재시도하고 응답 저장 실패는 저장부터 이어갑니다. 요청·저장·오류 중에는 내보내기를 막습니다. 이미 저장된 평가 열람·퇴장에 새 서버 응답은 필요하지 않습니다. 연결 실패를 임시 대사나 임의 점수로 대체하지 않습니다. 정식 보상·해금·게임 전체 저장은 별도 작업입니다.

환자 UI를 기존 씬에 추가하는 메뉴는 Edit 모드의 `Gamsamo > Install Patient Visits`입니다. 상담실 씬을 저장하고 해당 프리팹 편집 모드를 닫은 뒤 실행하면 기존 방·PC·치장을 보존하면서 씬과 프리팹을 함께 갱신합니다. 기존 로컬 방문 검사는 `Gamsamo > Run Patient Visit Checks`이며 AI 어댑터가 연결된 상태에서는 저장 보호를 위해 차단합니다. 이번 AI 연결은 `Gamsamo > AI` 메뉴와 공용 계약의 수동 검증 순서를 사용합니다. 결과는 Git 제외 영역 `artifacts/ui/patient-visit-checks.txt`에 남습니다.

내 프로필은 남녀 아바타와 이름·소속·소개를 표시하고, 사진은 6개 슬롯을 제공합니다. 실제 프로필 정보·사진이 없으면 빈 상태입니다. 환경설정은 1280×720 / 1920×1080 두 해상도·화면 모드와 전체/BGM/효과음 값을 편집하며 **적용으로 저장, 닫기·Esc로 미적용 변경 취소**합니다. 화면 변경은 실행 빌드에서 적용하고 Editor에서는 바꾸지 않습니다. 음원은 아직 없습니다.

상점은 `미리보기 · 가격 미정`과 잔액 `— C`를 표시합니다. 새 원본 카탈로그의 48종 가격은 모두 `null`이며 무료·0원으로 해석하지 않습니다. 원본 통화 `KRW`는 보존하고 UI만 기존 게임 단위 C로 표시하며, 환산이나 지갑 연결은 없습니다. 치장 선택은 PC를 닫아도 같은 Play 실행 동안 유지되고, Play 종료 후 다음 실행에서는 기본 외형으로 시작합니다. 소유권·재화·게임 저장은 변경하지 않습니다. 서류철은 책상 위 모습과 확대 기록부를 함께 바꾸며 기록 내용·빈 사진 칸은 유지합니다.

PC 창은 실제 상담실 배경 너비의 82% 안에서 비율을 유지합니다. 넓은 게임 뷰에 여백이 생겨도 PC와 상점이 상담실 화면 밖으로 커지지 않습니다.

UI 프리팹은 `Assets/_Project/Prefabs/ConsultationRoomUI.prefab`입니다. 첫 입장 전 기록은 `ConsultationRoomController.record`의 예시이고 입장 시 현재 환자의 이름·ID·날짜와 미확인 항목으로 바뀝니다. 서윤 AI는 검증된 공개 정보와 전체 상담 원문·평가를 기록부 표시 데이터로 전달합니다. 평가가 아직 없으면 진행 상태를 보여주며 서버 오류를 0점 결과로 만들지 않습니다. 다른 환자의 임상 설정과 사진은 임의로 추가하지 않습니다. 화면 비율이 다르면 상담실 좌우 또는 상하에 여백이 생깁니다.

Play 모드에서 `Gamsamo > Run UI Smoke Checks`로 클릭 영역, 모달 차단, 블러, 한글 표시, 텍스트 넘침, 닫기와 재열기를 검사합니다. 결과와 화면 캡처는 Git에서 제외된 `artifacts/ui/`에 저장됩니다. 씬을 처음 생성하는 도구는 `Gamsamo > Create Consultation Room Scene`이며, 기존 씬이 있으면 덮어쓰지 않습니다.

치장 48종과 블라인드·날씨 조합은 Play 모드의 `Gamsamo > Run Cosmetic Checks`로 검사합니다. 결과는 `artifacts/ui/cosmetic-checks.txt`에 남고 해당 폴더는 커밋하지 않습니다. PC 검사는 Play 모드의 `Gamsamo > Run PC UI Smoke Checks`로 실행합니다. 새 레이어·날씨·치장 연결은 `Gamsamo > Run Room Appearance Checks`로 검사합니다. PC·상점은 저장된 씬과 프리팹에 이미 연결되어 있습니다. 기존 기록부 씬에 PC를 추가하는 도구는 `Gamsamo > Install PC Desktop UI`이며, 이미 설치된 UI를 다시 만들지 않습니다. 실행 전 해당 씬을 저장하고 상담실 프리팹 편집 모드를 닫아야 합니다.

새 에셋 갱신 메뉴는 Edit 모드의 `Gamsamo > Apply Counseling Asset Pack`입니다. 저장된 씬과 프리팹 양쪽을 갱신하며, 프로필·사진·설정 창과 동적 상점 카드를 중복 생성하지 않습니다. `CosmeticCatalogImporter.Build()`가 원본 카탈로그·가격 미정·블라인드 구성·상대 경로를 검증하고 `Assets/_Project/Settings/CosmeticCatalog.asset`을 생성·갱신합니다. `CosmeticShopBuilder.Build(...)`는 빈 탭 템플릿 위에 썸네일·이름·선택 표시를 구성합니다.

미리보기 진입점은 `CosmeticAppearanceController.Preview(id)`이며 `RestoreCategory(target)`·`RestoreAll()`로 되돌립니다. 창문은 `ConsultationRoomAppearance.SetWindowVariant`로 테마별 블라인드 3단계×날씨 3종을 연결하고 `SetWeather`로 현재 날씨를 바꿉니다. 첫 창문 선택은 절반 상태이며 다른 테마와 날씨를 선택해도 현재 블라인드 단계는 유지합니다. 완성된 상태 이미지 위에 블라인드 오버레이를 다시 겹치지 않습니다. `PcDesktopView.TryApplyCosmetic`의 외형 교체 연결도 유지하며 소유권·결제 검증은 하지 않습니다. 자동 날씨 결정과 구매 로직은 후속 작업입니다.

### 화면 에셋과 폰트

- 환자: `Assets/_Project/Art/Characters/Patients/`의 6개 초상화와 `Assets/_Project/Settings/PatientVisits.json`의 이름·순서·임시 대사를 연결합니다. 초상화의 어두운 바탕은 전용 셰이더로 표시에서 제거하고 책상 경계에서 마스킹합니다. 이는 정식 환자 설정 JSON과 별개인 화면 시연 자료입니다.
- 대화창: `Assets/_Project/Art/UI/Dialogue/DialoguePanel.png` — 기본 제공 ImageGen으로 생성한 2172×724 투명 배경의 따뜻한 종이색 패널입니다. 인물 이름·대사는 이미지에 새기지 않고 TextMeshPro로 표시합니다. [생성 프롬프트와 사용 규칙](docs/plan01.md#patient-dialogue-art)을 통합 기획서에 보관합니다.
- 상담실: `Assets/_Project/Art/UI/CounselingPack/room/` — 기본 방·문·창문 3종·PC·서류철을 1920×1080으로 조립하고 전체를 함께 흐리게 합니다. 기존 단일 배경은 초기 생성 도구와 시작 화면 시안용으로 보존합니다.
- 기록부: `CounselingPack/room/medical-record-front.png` — 새 팩의 투명 외곽·빈 사진 칸 이미지를 사용합니다. 이전 `MedicalRecord.png`와 편집 기록은 보존합니다.
- PC·내부 창: `Assets/_Project/Art/UI/PcDesktop/`, `CounselingPack/profile/`, `photos/`, `settings/` — 이전 적용에서 기존 PC·상점 PNG 12개를 재사용하고 `pc-frame.png` 등 PNG 15개를 추가했습니다. 완성 배경·overview·preview·pc-open은 참고용으로 보존합니다.
- 치장: `Assets/_Project/Art/UI/CounselingPack/cosmetics/` — 원본 PNG 219개·JSON 2개·TXT 안내 2개로 총 223개 파일을 포함합니다. 원본 `catalog.json`과 `window/blind-states.json`을 기준으로 6분류×8테마를 연결합니다. 안내 문서는 참고자료이며 게임 규칙을 덮어쓰지 않습니다.
- 동적 상점: `Assets/_Project/Art/UI/CosmeticShop/templates/`의 빈 탭 PNG 6개를 사용합니다. `tabs/`의 완성 카드 PNG 6개와 `layout.json`도 새 제공본으로 갱신하되, 실제 UI는 템플릿과 개별 카드 데이터로 구성합니다. 레이아웃의 카탈로그 경로는 프로젝트 배치에 맞춘 `../CounselingPack/cosmetics/catalog.json`입니다.
- 기록부 편집에는 기본 제공 ImageGen을 사용했습니다. 편집 지시는 원본의 1024 × 1536 구도, 클립보드·종이 질감, 한글 제목·항목명·표 선을 유지하면서 외곽과 클립 구멍만 투명하게 만들고, 사진 속 인물만 제거해 테두리 안을 종이색 공백으로 채우는 내용입니다. [최종 편집 프롬프트](docs/plan01.md#asset-edit)는 통합 기획서에 보관합니다.
- 한글은 [Noto Sans CJK KR](https://github.com/notofonts/noto-cjk/tree/main/Sans/OTF/Korean)의 프로젝트 포함 폰트를 사용합니다. 라이선스는 `Assets/_Project/Fonts/OFL.txt`에 있습니다. TextMeshPro 필수 리소스는 `Assets/TextMesh Pro/`에 포함되어 있습니다.

시작 메뉴는 방향키·Enter와 마우스로 조작하며 Tab으로도 이동할 수 있습니다. `불러오기`는 저장된 진행 유무에 따라 활성화되며, 버튼 아래 저장 설명 문구는 표시하지 않습니다. 현재 `새 게임`은 초기 상담실 진입만 수행하며 별도 진행 ID·환자 초기화·자동 저장은 아직 생성하지 않습니다. 시작 화면 설정은 그래픽 위·오디오 아래 배치이며 PC와 `GameSettings`를 공유합니다. 적용은 저장, 취소·Esc는 미적용 편집을 취소합니다. 게임 종료는 확인 후 실행 빌드에서 종료하고 Editor에서는 확인 로그만 남깁니다. 비활성·미연결 목록은 기획서 15절의 시작 화면 표를 확인합니다. `새 게임`은 저장된 서윤 AI 사례를 초기화하지 않으며 게임 전체 진행 저장과 상담 AI 저장은 별개입니다.

상점은 상품 카드 크기를 유지하면서 하단 종이 여백을 늘려 안내·기본 복원 버튼을 테두리 안에 배치합니다. 기본 복원 버튼은 크림색 바탕·갈색 테두리를 사용하고, 창문 탭에는 창문 클릭 안내를 표시합니다. 빈 카드 이미지의 이름 자리 표시선은 같은 종이색 UI로 가려 상품명과 겹치지 않게 했습니다. 원본 PNG는 변경하지 않습니다.

시작 화면은 `Assets/_Project/Prefabs/StartMenuUI.prefab`의 인스턴스로 씬에 연결됩니다. `Gamsamo > Create Start Menu Scene`은 최초 생성 전용이며 기존 시작 씬·프리팹을 덮어쓰지 않습니다. 시작 화면 전용 검사는 해당 씬의 Play 모드에서 `Gamsamo > Run Start Menu Checks`로 실행합니다. 검사 후 상담실로 이동하며 보고서·캡처는 커밋 제외 `artifacts/start-menu/`에 남습니다.

## 개발 방향

| 항목 | 합의 내용 |
| --- | --- |
| Unity | 6.3 LTS, 현재 프로젝트 `6000.3.28f1` |
| 화면 구성 | 2D Built-In 렌더러, uGUI·TextMeshPro |
| 지원 환경 | Windows·macOS |
| 대화 | 환자 첫 발화 → 플레이어 서술형 답변 → LLM 환자 반응 반복, 완성 응답 수신 후 타이핑 효과 |
| 횟수 | 질문·답변 횟수 제한 없음, 공감·제안·질문을 자유롭게 섞어 정보 수집 |
| 입력·표시 | 서술형 입력창·전송·처리 상태 표시, 질문 사용량 바 없음 |
| 종료 | 사용자가 상담 그만하기 선택·종료 확정 → 접수된 응답·고정 상담자 안내·원문 저장 → 자동 평가 |
| 게임 안내 | 우측 상단 책 아이콘 클릭 → 확대 안내서 → 이전·다음 페이지로 기본 흐름 학습 (신규 기획) |
| 평가 | 환자 변화·상담자 대응 각각 4항목 × 25점, 두 축 각각 70점 이상일 때 완료 |
| 평가 기록 | 서윤 변화는 누적 원문, 상담자 대응은 이번 회차 발언, 전체 구간 지지·반대 근거 검토 |
| 환자 | 총 6명, 초급·중급·상급 단계별 2명, 모두 비슷한 난이도, 고정 설정과 환자별 상담 기록 |
| 정보 공개 | LLM이 공개 후보를 제안하고 Unity가 조건을 확인하여 항목별 공개 |
| 성장 | 누적 완료 환자 수에 따라 자동 승급, 전체 환자 완료 시 엔딩 |
| 엔딩 크레딧 | 6명 전원 행복한 후일담, 중앙 제작진·좌우 사진 위 실제 상담자 발언 한 줄, 위에서 아래로 천천히 이동 (기획 확정) |
| 재화·상점 | 두 축 평균 × 2를 기준으로 환자별 최고 보상 차액 지급 + 최초 클리어 100C, 치장 전용 상점 |
| 저장 | 자동 저장만 제공, 원문 별도 보존, 이어하기·재상담·새 실험 구분 |
| 기억 | 약 12,000 입력 토큰에서 오래된 내용 요약, 최근 약 6왕복 원문, 입력·출력 합계 16,384토큰 이내 |
| 서윤 실험 모델 | `RedHatAI/Qwen3.5-9B-quantized.w4a16` |
| 서버 | FastAPI + LangGraph + vLLM, 기존 Conda `game-ai` 환경 |
| 외부 연결 | 임시 HTTPS 터널, 접속 주소·접근 키는 로컬 설정으로 관리 |

서윤 실험의 모델과 서버 구성은 위와 같이 확정했습니다. 모델 설정·서빙 연동·품질 및 속도 검증 결과는 `ai/`와 `server/`에 기록합니다.

- **Unity:** 환자 발화 표시·서술형 입력·전송·상담 그만하기, 진행도, 정보 공개 확정, 점수 기반 보상·치장 구매·장착, 승급, 엔딩과 자동 저장 연동을 담당합니다.
- **대화 서버:** 환자 설정·기억에 따른 첫 발화와 자유 서술형 응답, 사용자 종료·고정 안내·평가를 처리합니다. 첫 발화는 별도 `opening`으로 보존하고 가짜 상담자 발언을 만들지 않습니다. 클라이언트가 종료 원문 저장에 성공한 이후 두 축 평가를 호출합니다.
- **추론 엔진:** 모델을 실행합니다. 모델·서빙 도구가 바뀌어도 게임의 API 규격을 유지하도록 연결부를 분리합니다.
- **공용 데이터:** 환자 JSON 원본은 `Assets/StreamingAssets/GameData/Patients/` 한 곳에서 관리합니다. API·데이터 규격은 프론트와 백엔드가 `contracts/`에서 맞춥니다.

## 협업 기준

1. Unity 담당자가 프로젝트 버전과 렌더러를 관리하고 기본 설정을 공유합니다. 현재 버전은 `ProjectSettings/ProjectVersion.txt`를 기준으로 하며, uGUI와 TextMeshPro를 사용합니다.
2. 환자 데이터 형식과 대화 API 요청·응답 규격을 먼저 합의한 뒤 각자 구현합니다.
3. Unity 에셋과 연결된 `.meta`는 함께 커밋합니다. 씬을 동시에 수정하기보다 담당자를 정하고 프리팹·스크립트·데이터로 작업을 나눕니다.
4. 모델 가중치, 빌드, 캐시, 가상환경과 실제 접근 키는 Git에 넣지 않습니다. Unity가 추후 생성하는 `.meta`와 패키지 잠금 파일은 공유합니다.
5. 상담 기록과 사용자 설정은 실행 환경의 로컬 저장 공간에 보관하도록 구현합니다.
