# 서윤 터미널 상담 실험

서윤 1명과 자유롭게 대화하고 종료 후 두 점수로 평가하는 서버 실험이다. Unity 씬·UI·성장·재화는 이 구현에 포함하지 않는다.

이 문서는 **A6000 이전을 위해 보관한 기존 구현의 실행법**이다. 현재 코드는 여전히 주질문 5개·무료 후속질문·수동 저장을 사용한다. 최신 게임 기획의 **질문만 총 5개, 순수 공감은 별도, 다섯 번째 답변 뒤 마무리, 자동 저장 전용**은 아직 코드에 반영하지 않았다. 이전 구현을 새 규칙의 완성본으로 사용하지 않는다.

- [환경변수·설치·A6000 이전](environment.md): 실제 설정 이름, 기본값, 패키지 버전, 모델 준비와 기록 이전.
- [진행 상황·검증·남은 작업](progress.md): 구현된 기능, 한국어 품질 문제, 최신 기획과의 차이, 후속 작업.
- [게임 기획](../docs/plan01.md), [현재 실험 API](../contracts/README.md).

## 현재 서버에서 실행

```bash
conda activate game-ai
# 저장소 루트에서 실행한다. 다른 서버에서는 해당 clone 경로를 사용한다.
python tools/run_experiment.py
```

이 명령은 vLLM, FastAPI, 터미널을 순서대로 실행한다. 최초 실행에는 GPU 커널 준비 시간이 걸릴 수 있다. `상담자 >` 입력란에 `x`만 입력하고 Enter를 누르면 대화 프로그램과 이 명령이 실행한 두 서버·GPU 작업이 함께 종료된다. 확정된 대화는 저장되며 종료 명령으로 최종 평가를 요청하지 않는다. 이미 서버가 실행 중이라면 `python tools/chat.py`로 접속한다. 이 경우 `x`는 대화 프로그램만 종료하고 별도로 실행한 서버는 유지한다. SSH 연결 종료 후에도 확정된 대화는 파일에 남는다.

서버를 각각 켜려면 별도 터미널에서 다음 명령을 사용한다.

```bash
python tools/serve_model.py
python tools/serve_api.py
python tools/chat.py
```

각 서버는 localhost의 8000·8001 포트에만 열린다. 이번 실험에는 HTTPS 터널이 필요 없다. API 키가 필요한 경우 `server/.env.example`에 적힌 환경 변수를 셸에서 설정한다. 예제 파일은 자동으로 읽지 않는다.

## 처음 환경을 구성할 때

이 프로젝트는 Python 3.11 환경 하나에 API와 모델 실행 패키지를 함께 설치한다. 기존 환경을 변경하기 전에는 패키지 목록을 보관한다. 새 서버의 준비 순서와 확인된 버전은 [환경 안내](environment.md)를 따른다.

```bash
conda activate game-ai
python -m pip install -e './server[serve,test]'
python -m vllm.entrypoints.cli.main download-kernels
python tools/download_model.py
python -m pip check
```

모델·리비전·문맥 길이·역할별 생성 설정은 `ai/configs/seoyun.json`에서 관리한다. 기본 모델은 RedHatAI/Qwen3.5-9B-quantized.w4a16이며, 원본 모델이나 문맥 크기로 자동 대체하지 않는다. 다운로드에 성공해야 리비전 확인 파일이 생성된다. 가중치와 GPU 로그는 Git에서 제외된다.

기존 서버의 Conda OpenCV는 pip가 교체할 수 없는 설치 정보를 가지고 있어 OpenCV 세 패키지(opencv, py-opencv, libopencv)를 제거하고 pip의 headless 패키지로 교체했다. 환경 변경 전 목록은 `ai/outputs/env-backups/`에 보관했다. PyTorch 2.14.0에 맞는 NVSHMEM 3.4.5를 사용하며 기존 PyTorch 불러오기 오류를 해결했다.

## 현재 구현의 상담과 명령

플레이어가 먼저 인사한다. 단순 인사와 공감은 주질문을 사용하지 않는다. LLM이 질문을 분류하지만 실제 카운터는 코드가 변경한다. 한 번에 여러 주제를 보내면 하나씩 다루며 새 주제를 다룰 때마다 기회를 사용한다. 5개 이후의 새 주제는 다음 상담으로 미룬다.

마지막 주질문 뒤 최소 한 번 더 발언할 수 있다. 이후 미해결 후속질문과 실제 응답을 보고 모델이 자연스러운 마무리를 판단한다. 후속 대화 횟수에는 상한이 없다. 종료 후 대화가 먼저 저장되고 평가를 별도로 실행한다.

| 명령 | 동작 |
|---|---|
| `/save` | 현재 확정 상태를 수동 슬롯에 저장 |
| `/load auto`, `/load manual` | 현재 실험의 저장 상태 복원 |
| `/retry` | 연결·출력 오류로 확정하지 못한 발언 재시도 |
| `/evaluate` | 종료된 상담의 평가만 재시도 |
| `/next` | 기준 미달 후 이전 기억을 이어 재상담 |
| `/new` | 기존 기록을 보관하고 초기 서윤으로 새 실험 |
| `/cases`, `/open 실험_ID` | 보관된 실험 확인·불러오기 |
| `/status`, `/help` | 상태·도움말 |
| `x`, `/quit` | 대화 프로그램 종료. 통합 실행 시 API·모델도 함께 종료 |

터미널의 `주질문` 횟수·분류·처리 시간은 기존 구현을 확인하는 표시다. 최신 게임은 실제 화면에도 **총 질문 사용량 0/5~5/5**를 표시할 계획이며, 현재 표시와 계산을 그대로 연결하면 안 된다. 실패한 발언은 실행 중인 터미널에서 `/retry`로 다시 보낼 수 있으며, 진행 상태에는 확정된 발언만 저장된다.

`x`는 입력 프롬프트에서 읽는 종료 명령이다. 이미 실행 중인 모델 요청을 동시에 취소하는 명령은 아니다. 정상 상담 종료·평가와 프로그램 종료는 다르며, `x`로 나가면 확정 상태에서 다음에 이어간다. `X`, `/quit`, `/exit`도 지원한다.

## 기억과 저장 경계

원문은 모두 클라이언트에 보존한다. 기본 저장 위치는 `~/.local/share/gc-gamsamo/seoyun/`이며 `XDG_DATA_HOME` 또는 `SEOYUN_DATA_DIR`로 프로젝트 밖의 위치를 지정할 수 있다. 실험마다 `auto.json`과 `manual.json`을 따로 관리하고, 새 실험은 기존 실험 폴더를 덮어쓰지 않는다.

한 JSON에 원문·정보 공개·상담별 주제와 결과·구조화 기억·버전을 저장한다. 임시 파일에 쓴 후 교체하며 수동 슬롯은 자동 저장으로 변경하지 않는다. 서버에는 데이터베이스나 영구 세션 캐시를 두지 않는다. LangGraph는 매 요청의 상태에서 실행되며 vLLM의 KV 캐시는 저장된 기억을 대신하지 않는다.

모델 입력이 약 12,000토큰에 이르면 오래된 턴을 출처 ID가 있는 구조화 기억으로 압축한다. 최근 6왕복 보존을 우선하되 실제 입력·출력 합산 16,384토큰 한도를 우선한다. 새 입력 자체가 너무 크면 원문을 버리는 대신 오류를 반환한다. 요약은 고정 인물 설정을 수정하지 않는다.

## 평가

환자 축: 자기 가치 분리, 감정 인정, 카페 능력 인정, 현실적인 선택·휴식 계획.

상담자 축: 공감·경청, 단정하지 않는 탐색, 자율성 존중, 경제·구직 현실 고려.

각 항목 25점이며 두 축 모두 70점 이상이어야 클리어한다. 환자 축은 누적 상담, 상담자 축은 이번 상담의 발언만 근거로 사용한다. 양수 점수에는 실제 발언의 지지 근거가 필요하다. 인용 문자열·발언 ID·발언자를 검사하고 합산과 클리어는 코드가 계산한다.

평가 입력에는 원문 구절마다 짧은 번호를 붙인다. 모델은 항목별 점수와 근거 번호·지지/반대 구분을 선택하고, 코드는 해당 구절을 원문 그대로 인용하여 원래 턴 ID와 연결한다. 인용문을 모델이 고쳐 쓰게 하지 않으며, 최종 평가의 선택 가능한 근거도 각 축의 발언자·상담 범위로 제한한다.

원문 전체가 평가 문맥에 들어가지 않으면 모든 구간을 읽어 항목별 지지·반대 근거를 추출하고, 필요하면 출처를 유지해 재압축한다. 대화용 요약만으로 점수를 매기지 않는다. 내부 추론 내용은 사용자 기록에 저장하거나 화면에 출력하지 않는다.

## 검증

실제 GPU 측정 결과와 확인된 한계는 [진행 상황과 검증 기록](progress.md)에 정리했다. 아래 자동 테스트와 실모델 스크립트는 기존 주질문 규칙을 검증하며, 최신 총 질문 5개 규칙의 검증은 아니다.

```bash
python -m pytest server/tests -q
python ai/evaluation/terminal_smoke.py
python ai/evaluation/long_context_smoke.py
```

첫 명령은 실제 모델이 필요 없는 경계·저장·통신 테스트다. 두 번째는 실행 중인 실제 모델과 API로 대화·종료·평가를 검증하며 사용자의 저장 슬롯을 건드리지 않는다. 결과는 Git 제외 영역 `ai/outputs/real-model-smoke.json`에 남는다. 일반 대화의 목표는 예열 후 보통 10초 이내이며 요약·종료·평가 시간은 별도로 본다.

세 번째는 두 번째 검증의 대화를 반복한 합성 기록으로 14,000토큰 이상의 입력, 기억 요약, 원문 보존, 저장 복원, 전체 구간의 평가 근거 추출을 검사한다. 결과는 `ai/outputs/long-context-smoke.json`에 남으며 이 합성 기록의 점수는 연기·상담 품질 평가로 사용하지 않는다. GPU를 공유하므로 실제 모델 검증은 하나씩 실행한다.

환자 JSON은 Unity와 공유하는 원본이다. API 규격과 예제는 `contracts/`를 참조한다. 이 서버 실험에서 확인한 완료 결과를 향후 Unity가 게임 진행·보상에 반영한다.
