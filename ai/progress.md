# 서윤 AI 베타 진행 상황

## 현재 구현과 검증

환자가 먼저 말하고 플레이어가 자유로운 서술형으로 답한다. 공감·요약·여러 질문을 정상 대화로 처리하며 질문 분류·차감·복합 질문 거절은 제거했다. 사용자가 상담 종료를 확정하거나 CLI의 `/finish`를 실행하면 **상담은 여기까지 하겠습니다. 오늘 수고하셨습니다!**를 상담자 안내로 저장하고 평가한다. 고정 안내는 평가·기억 근거에서 제외한다.

- `format_version=4`, `content_version=seoyun-4.0`, 자동 저장 `v4/`. 형식 1·2·3의 원문과 저장은 보존하며 자동 변환하지 않는다.
- `/start`는 새 상태와 환자 첫 발화, `/open`은 빈 회차의 첫 발화, `/revisit`는 평가가 끝난 미완료 환자의 다음 회차와 첫 발화를 반환한다. 첫 발화는 가짜 상담자 입력 없이 별도 `opening` 원문으로 저장·요약·평가한다.
- 서버 자동 검사 90개를 통과했다. 새 첫 발화·복수 질문 포함 12턴 대화·첫 발화 저장 실패 후 재시도·요청하지 않은 대화가 섞인 응답 거부·상담 종료·재상담·최근 6왕복 보존을 포함한다. OpenAPI와 합성 예제는 같은 코드에서 생성하며 모델 품질 증거로 사용하지 않는다.
- 정식 환자 데이터는 서윤 한 명뿐이다. `/health`가 지원 환자를 알리고 다른 환자의 `/start`는 `unsupported_patient`로 거절한다. 다른 다섯 명에게 서윤의 임상 설정이나 평가 기준을 복제하지 않았다.
- 실제 Qwen 프로필로 형식 4의 환자 첫 발화·공감/복수 질문을 포함한 8턴·중간 저장 복원·사용자 종료·평가·평가 재전달을 확인했다. 공개 HTTPS에서도 인증 거부·첫 발화·자유 대화·재상담·종료 후 차단·형식 오류를 확인했다. 첫 발화에 필요한 모델 전용 제어 신호를 보완했고 상담 원문·기억·평가에 가짜 상담자 발언은 넣지 않는다.
- Unity의 통신·검증·상담 저장·재시도 연결 계층을 추가했다. C# 계약·저장 검사 103개와 실제 HTTPS API 검사 14개를 통과했다. **입력창·전송 버튼은 미구현**이며 팀원이 [공개 함수·이벤트 명세](../contracts/README.md#unity-text-input)에 연결한다. Unity Editor Play·한글 입력·Windows/macOS 실행 검사는 PR 이후 팀원이 수행한다.
- 합성 긴 기록으로 기억 요약·최근 6쌍 보존·원문 저장 복원·실제 분할 평가를 통과했다. 공개 HTTPS에서도 새 회차 시작→대화→종료→평가와 평가 저장·복원·재전달을 확인했다. 이 검사는 현재 서버에서 공개 터널을 경유한 것이며 별도 PC의 Unity 실행 검사는 아니다.
- 프록시에서 JSON이 아닌 오류 페이지가 와도 Python 클라이언트가 기존 요청을 유지하도록 수정했다. 평가와 긴 기록 처리는 일반 대화보다 오래 걸릴 수 있으므로 평가 중 표시·연결 실패·같은 요청 재시도를 구분한다.
- 형식 3에서 보고한 Qwen 후보의 6개 질문·수동 종료·저장·평가·HTTPS 인증 통과는 이전 검증 결과로 보존한다. 새 첫 발화와 변경한 프롬프트의 동작을 보장하지 않는다. 형식 2의 기준 모델 긴 원문 요약·근거 평가와 20개 상황×2 비교 역시 이전 이력이다.
- 기본 모델은 기존 프로필을 유지한다. EXAONE은 행사 라이선스 조건 확인 전 실행하지 않는다. 개인 접속 키·상담 원문·측정 로그는 공개 변경에 추가하지 않는다.

실행은 [AI README](README.md), 규격은 [contracts](../contracts/README.md), 기준·일정·작업 이력은 [통합 기획서](../docs/plan01.md)를 따른다.

## 구현된 기능과 연결 지점

| 영역 | 구현 상태·주요 진입점 |
|---|---|
| 모델 준비 | `tools/download_model.py`: 고정 리비전 다운로드와 `.seoyun-model.json` 기록. 가중치는 Git 제외 |
| 모델 실행 | `tools/serve_model.py`: 텍스트 전용 vLLM, localhost:8000, 단일 동시 요청 설정 |
| API | `server/app/main.py:create_app()`: `/health`, `/v1/dialogue/turn`, `/v1/dialogue/evaluate`; 요청 직렬화와 선택적 Bearer 인증 |
| 대화 흐름 | `DialogueService`: LangGraph에서 기억 준비 → 주제 분류 → 환자 대사 → 종료 판단 → 마무리 |
| 모델 요청 | `VllmClient.generate()`: 역할별 설정, JSON Schema, 입력·출력 토큰 예산, 잘못된 출력에 한 번 수정 요청 |
| 인물 설정 | `Assets/StreamingAssets/GameData/Patients/seoyun.json`: 서윤의 공개·비공개 설정, 평가 항목. 원본은 이 파일 한 곳 |
| 기억 | `MemoryManager.prepare()`: 원문을 보존하면서 오래된 부분을 출처가 있는 구조화 기억으로 요약 |
| 평가 | `EvaluationService.evaluate()`: 누적 환자 발언·현재 회차 상담자 발언, 긴 원문 전체 구간의 근거 추출, 8개 항목 검증과 두 축 합산 |
| 저장·복원 | `SaveStore`, `SessionClient.accept()`: 클라이언트가 전체 상태 저장, 임시 파일 교체, 응답 ID·revision 검사, 불러오기 이전 응답 차단 |
| 터미널 | `tools/chat.py`: 자유 입력, 자동·수동 저장, 재시도, 재상담, 기록을 보존한 새 실험 |
| 통합 실행·종료 | `tools/run_experiment.py`: 자신이 시작한 API·vLLM 프로세스 그룹 관리. 입력창의 `x`로 CLI가 종료되면 해당 서버도 종료 |

서버 데이터베이스나 LangGraph 영구 체크포인터는 없다. 요청에 클라이언트의 전체 확정 상태를 전달한다. vLLM 캐시는 영구 기억이 아니며, Unity의 보상·상점·승급이나 6명 환자 처리는 이 실험에 구현하지 않았다. API와 예제는 [contracts](../contracts/README.md)에 있다.

## 최신 기획과 아직 다른 부분

| 항목 | 현재 코드 | 최신 기획·후속 작업 |
|---|---|---|
| 질문 차감 | `neutral / followup / new_topic`; `new_topic`만 주질문 기회 사용 | 질문이면 모두 1회. 후속·반복 확인도 포함, 질문 없는 공감·인사는 0회 |
| 복합 질문 | 새 주제를 순서대로 다루거나 다음 회차로 미룸 | 답변·차감 전에 한 질문씩 나누도록 안내하는 안 |
| 다섯 번째 이후 | 최소 한 번 추가 발언을 허용하고 LLM이 마무리 가능 여부 판단 | 다섯 번째 답변 뒤 입력을 닫고 짧게 마무리, 원문 저장 후 평가 |
| 종료 상태 | `Session.topics`, `post_budget_turns`, `Closure` 중심 | 총 질문 수·마지막 답변·마무리 상태를 코드로 관리하도록 스키마·프롬프트·테스트 수정 필요 |
| 저장 | `auto.json`과 `manual.json`, `/save`, `/load manual` 지원 | 게임은 자동 저장만 제공 |
| 표시 | 터미널에 주질문 횟수 표시 | 실제 게임에도 총 질문 사용량 표시; Unity 연결 전 규격 변경 필요 |
| 환자·게임 진행 | 서윤 1명, 두 축 평가·클리어만 구현 | 6명, 자격증, 보상, 상점, 엔딩, 안내서와 UI 연결 필요 |

새 규칙을 구현할 때 기존 저장 파일의 `topics` 개수를 총 질문 수로 간주하면 안 된다. 기존 `followup`은 횟수에 포함되지 않았으므로 저장 형식 버전·이전 실험 보존·새 규칙 적용 범위를 함께 정해야 한다. `main_question_budget`, `Classification`, `Turn.kind`, `Session`, `DialogueService.classify()/check_closure()`, CLI, API 예제와 기존 테스트가 변경 대상이다.

질문 예시 제시와 첫 상담 고정 보상은 대화에서 제안했지만 채택·구현되지 않았다. 이번 보관 작업에서 이를 확정 사항으로 추가하지 않는다.

## 직접 체험에서 확인한 문제

- 한국어 조사와 문맥: 사용자가 지적한 “부모님에서 보내는 채용 정보”, “말씀드릴 수 있는 게 아무것도 없네요”처럼 어색하거나 무엇을 뜻하는지 이해하기 어려운 발언이 발생했다. 첫 답변에서도 관찰되어 긴 대화 요약만으로 설명할 수 없는 문제다.
- 대화 진행: 화제 전환을 요청해도 주제를 되묻거나 비슷한 답변을 반복하는 사례가 있었다. 기존 주질문 분류는 주제명이 실제로 새로운지까지 코드로 보장하지 않는다.
- 품질 검증의 범위: 현재 `validate_reply()`는 비어 있는 대사, 일부 문자 혼입, 허용되지 않은 정보 ID 등을 검사한다. 한국어 문법, 질문에 대한 답변의 적절성, 의미 반복을 검증하지는 않는다. 정보 ID 검증이 대사 의미 전체의 일관성을 보장하는 것도 아니다.
- 사용자는 모델 추론 능력을 주요 원인으로 의심하여 A6000 서버에서 후속 실험을 진행할 예정이다. **모델 크기·4비트 양자화·프롬프트·생성 설정 중 원인은 아직 분리 검증하지 않았다.** 현재 환자 대사는 thinking을 끈 상태이고 최종 평가에만 제한된 thinking을 사용한다.

GPU만 바꾸어 문장 문제가 해결된 것으로 판단하지 않는다. 같은 모델·리비전·프롬프트·생성 설정으로 기준 응답을 먼저 비교하고, 모델이나 설정을 바꿀 때에는 변경 내용과 품질·지연 시간을 함께 기록한다. 개인 대화 원문과 저장 파일 전체는 PR에 포함하지 않는다.

긴 기록 검증은 실제 검증 대화를 반복해 문맥을 늘린 합성 테스트다. 여기서 나온 점수는 캐릭터 연기나 상담 품질의 측정값으로 사용하지 않는다. 실행 시간도 이 서버에서 측정한 표본이며 모든 입력의 지연 시간을 보장하지 않는다.

### 당시 검증 중 보완한 부분

- 기존 PyTorch 불러오기 오류와 Conda/pip OpenCV 충돌을 해결하고 필요한 FlashInfer GPU 커널을 설치했다. 변경 전 환경 목록과 설치 보고서를 보관했다.
- Transformers 5의 기본 반환값이 토큰 배열이 아닌 `BatchEncoding`인 점을 반영했다. 실제 토큰 배열 길이로 한도를 계산하고 회귀 테스트를 추가했다.
- 현재 상담자 발언을 과거 기록과 구분해 전달하고 신규/후속 질문의 구분 예시를 보강했다.
- 한국어 대사의 한자·일본어 혼입, 존재하지 않는 공개 정보 ID, 잘못된 주제 ID를 출력 규격과 검증으로 제한했다.
- 요약 출처를 발언자별 번호로 제한했다. 평가는 원문 구절 번호를 선택하게 하고 코드가 정확한 인용과 원래 발언 ID를 복원한다.
- 응답 ID·기준 상태 버전·마지막 턴을 검사하고, 실패한 평가가 이미 저장된 상담을 변경하지 않도록 확인했다.

### 검증 결과의 한계

한국어 문장에 어색한 표현이 남아 있고, 주질문과 후속질문의 구분은 표현과 앞선 대화에 따라 달라질 수 있다. 발견한 분류 사례는 지침을 보완해 확인했지만 자유 입력 전체의 정확도를 검증한 것은 아니다. 점수와 설명 역시 이 모델의 판단이므로 직접 대화하며 캐릭터 연기·종료 타이밍·평가 근거를 검토해야 한다.

잘못된 모델 출력은 해당 단계에서 한 번 수정 요청한다. 계속 실패하면 그 턴을 확정하지 않으며 `/retry`로 다시 시도할 수 있다. 평가 실패 시 종료된 원문은 보존하고 `/evaluate`로 평가만 다시 요청한다. 모델이나 문맥 길이를 자동 변경하지 않는다.

## 로컬 검증 산출물과 이전 범위

모두 Git 제외 영역 `ai/outputs/`에 있다.

- `real-model-smoke.json`: 마지막 전체 상담, 원문·상태·평가·시간
- `long-context-smoke.json`: 긴 기록 요약·출처·원문 해시·평가 결과
- `classification-check.json`: 마지막 분류 지침의 대상 입력 검증
- `launcher-check.json`, `launcher-check.log`: 실제 터미널·저장·재상담·시작/종료 검증
- `verified-environment.json`, `verified-pip-freeze.txt`: 확인한 환경 버전
- `env-backups/`, `install-report.json`: 환경 변경 전 목록과 설치 기록

개인 저장 영역은 검증에 사용하지 않았다. 터미널 저장 검증에는 프로젝트 밖의 임시 폴더를 사용했다.

이 산출물과 `ai/models/`의 가중치는 Git clone만으로 옮겨지지 않는다. 실행 재현에는 고정 리비전 모델을 다시 다운로드하면 된다. 사용자가 이전 기록과 측정 원문을 보존하려면 저장 영역과 필요한 산출물을 별도로 옮긴다. GPU별 컴파일 캐시나 기존 Conda 환경 디렉토리를 그대로 복사하는 것을 재설치 대신 사용하지 않는다.

## PR #10 당시 정리한 후속 작업

아래는 당시의 순서다. 현재 우선순위·모델 후보·완료 기준은 [통합 후속 계획](../docs/plan01.md#ai-next-plan)이 대체한다.
