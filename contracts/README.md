# 서윤 실험 API

이 규격은 A6000 이전 전의 **기존 주질문 5개 실험**을 보관한 것이다. 최신 기획의 총 질문 5개·다섯 번째 답변 뒤 마무리는 아직 반영하지 않았다. 스키마와 코드의 차이는 [AI 진행 상황](../ai/progress.md)에 기록한다.

이 규격은 **클라이언트가 저장을 소유하는** 대화 API다. 서버가 상담 ID만 받아 과거 기록을 조회하는 방식이 아니다. 모든 요청에 해당 실험의 확정 상태를 전달한다.

| API | 입력 | 출력 |
|---|---|---|
| `GET /health` | 없음 | API 상태, 모델 준비 상태, 콘텐츠/모델 버전. 추론 서버가 준비되지 않으면 503 |
| `POST /v1/dialogue/turn` | `state`, `session_id`, `turn_id`, `text` | `StateResponse` |
| `POST /v1/dialogue/evaluate` | `state`, `session_id`, `request_id` | `StateResponse` |

키를 설정한 경우 두 POST 요청에 `Authorization: Bearer ...`를 넣는다. 키는 코드·저장 파일에 넣지 않는다.

`StateResponse`에는 `case_id`, `session_id`, `request_id`, `base_revision`, 갱신된 `state`, `replayed`가 있다. 클라이언트는 요청 식별자·기준 revision·현재 활성 실험을 확인한 뒤 상태를 통째로 확정하고 자동 저장한다. 불러오기 전 시작한 응답과 이미 반영한 응답은 무시해야 한다. 정상 변경은 revision을 1 늘리며 이미 확정된 턴/평가의 재전달은 `replayed=true`다.

`state`는 형식·콘텐츠 버전, 실험 ID, 환자 ID, 공개 정보 ID, 미룬 주제, 구조화 기억, 상담별 원문·주제·종료·평가를 포함한다. `sessions[-1]`이 현재 상담이며 평가 완료 후 재상담을 시작할 때 새 상담을 추가한다. 새 실험은 새 ID와 초기 상태를 사용한다.

각 발언의 평가 출처는 `턴_ID:user` 또는 `턴_ID:patient`다. patient 발언에는 해당 턴의 마무리 대사도 포함된다. 평가 결과는 8개 항목별 0~25 정수와 근거, 코드가 계산한 두 총점 및 완료 여부를 갖는다.

모델 내부 요청에는 원문 구절에 짧은 번호를 붙여 근거 선택에 사용한다. API 응답에는 이 번호 대신 원래 발언 ID와 정확한 원문 인용을 반환한다. 대화 요약은 평가 원문을 대신하지 않는다.

현재 상태의 주제 분류 정보는 기존 실험 진단용이다. 최신 기획의 실제 게임에는 총 질문 사용량을 표시해야 하지만, 현재 `topics` 개수를 그 값으로 사용할 수 없다. 보상·잔액·자격증 결정은 이 API에 포함하지 않는다.

오류는 `detail.code`와 `detail.message`로 반환한다. 잘못된 요청 데이터는 FastAPI의 422 검증 오류다. 실패한 대화 응답은 반영하지 않는다. 마지막 대화를 저장한 후 평가 요청이 실패한 경우 그 상담은 종료된 상태로 유지하고 평가만 다시 호출한다. 동일한 과거 상태로 다시 요청하면 서버가 새 결과를 생성할 수 있으므로, 중복 반영 방지와 저장된 성공 결과 재사용은 클라이언트가 담당한다.

정확한 필드·제약은 `dialogue.openapi.json`에 있다. 서버의 `/docs`에서도 확인할 수 있다.
