## 1. 게임 개요와 주제

| 항목 | 내용 |
| --- | --- |
| 장르 | 시뮬레이션, 선택의 중요성, 스토리 중심, 캐주얼 |
| 플레이어 | 초급 상담사로 시작해 다양한 환자의 사연을 듣는 상담사 |

| 게임 안내 | 우측 상단 책 아이콘 클릭 → 확대 안내서 → 페이지 넘김 |

### 1.1 콘텐츠 방향

`[확정·사용자 설명]` 국내의 다양성·포용·편견·차이에 대한 실제 사례를 수집하고 스토리를 직접 각색했다. 플레이어는 상담에 참여해 인물의 이야기를 듣고 공감하며 서로 다른 맥락을 이해한다. 개별 각색 원문과 사례 목록은 콘텐츠 담당자가 공용 환자 데이터에 연결한다.

`[기획 해석]` 해커톤 주제 3번인 다른 시선·공감·이해를 중심으로, 고정관념을 다시 바라보는 사례는 1번과 연결된다. 세대·공동체 등 현실 문제를 다루는 사례는 4번과도 연결할 수 있다. 접근성 기능을 별도로 구현·검증하지 않은 상태에서 2번까지 충족했다고 주장하지 않는다.

주요 분위기 레퍼런스는 [Coffee Talk](https://store.steampowered.com/app/914800/Coffee_Talk/?l=koreana)다. 고정된 실내 공간, 인물 중심의 대화, 차분한 색감과 음악을 참고한다. 음료 제조는 기존 범위와 같이 제외한다.

## 2. 전체 진행과 상담 상태

```text
새 게임 / 이어하기 → 상담실 → 환자 선택 → 상담 시작
  → LLM이 질문 포함 여부 확인 → 유효한 질문 하나에 응답
  → 코드가 질문 1개 사용 확정 → 사용량 바 갱신
  → 대화·기억·공개 정보 자동 저장
  → 총 질문 5개 사용 후 새 질문 입력 종료
  → 다섯 번째 답변 완료 후 짧은 마무리 응답
  → 남은 고민은 다음 상담 기억으로 보존
  → 마무리 대화까지 원문 저장 → 평가 자동 호출
      ├─ 두 평가축 각각 70점 이상: 상담 완료 → 점수 보상·최초 클리어 보너스 → 완료 인원·승급 반영
      └─ 어느 한 축이라도 70점 미만: 점수 보상 정산 → 기억 유지 → 재상담 대기
  → 결과·재화 자동 저장 → 모니터 상점에서 치장 아이템 구매·장착
  → 전체 필수 환자 6명 완료 여부 확인 → 엔딩 또는 다음 상담
```

| 상태 | 의미 | 다음 처리 |
| --- | --- | --- |
| 방문 대기 | 아직 공개되지 않은 단계의 환자 | 진행 조건 충족 시 방문 가능 |
| 방문 가능 | 첫 상담 또는 재상담을 시작할 수 있음 | 새 상담 회차 생성 |
| 상담 중 | 질문 종류와 관계없이 5개 이내에서 대화 | 질문 사용량 확인 또는 이어하기 |
| 마무리 대화 중 | 5개 사용 완료, 다섯 번째 답변과 정리 진행 | 새 질문 차단, 원문 저장 후 평가 |
| 평가 대기 | 다섯 번째 답변·마무리 저장 완료 | 자동 평가, 오류 시 재시도 |
| 재상담 대기 | 한 축 이상 70점 미만 | 기억을 이어받는 새 회차 시작 |
| 상담 완료 | 두 축 모두 70점 이상 | 완료 기록 유지, 중복 집계 금지 |

`[제안]` 첫 상담에서 기록부·질문 사용량·우측 상단 책 안내서를 소개한다. 시간제한 없이 읽고 입력하며, 강제 체력 제한은 두지 않는다. 환자 기록 열람 중에는 상담 단계가 진행되지 않는다.

## 3. 상담당 질문 5개와 횟수 계산

### 3.1 질문 구조 `[확정]`

- 상담 회차마다 **질문을 총 5개까지만** 할 수 있다.
- **주질문·후속질문 구분 없이 질문이면 모두 1회를 사용**한다. 같은 주제의 추가 질문·반복 확인도 예외가 아니다.
- 질문 역할·주제 순서·대질문과 소질문 구분을 두지 않는다. 후속질문을 무료로 계속하는 기존 규칙은 폐기한다.
- LLM은 발언에 질문이 들어 있는지 판단하고, 코드는 남은 기회와 유효 응답을 확인해 사용량을 계산한다. 새 주제인지 여부로 무료 질문을 허용하지 않는다.

### 3.2 질문 판정과 복합 입력 `[구체화 제안]`

| 입력 | 기회 사용 | 처리 |
| --- | --- | --- |
| 새로운 주제의 질문 1개 | 1회 | 답변 완료와 함께 차감 |
| 기존 주제의 후속질문·명료화·반복 질문 1개 | 1회 | 주제와 관계없이 동일하게 차감 |
| 물음표 없이 설명·확인을 요청하는 발언 | 질문이면 1회 | 문장 부호가 아니라 의도를 판단 |
| 순수한 인사·공감·요약·감사 | 0회 | 질문·답변 요구가 섞이지 않은 경우에만 해당 |
| 공감과 질문 1개가 함께 있는 발언 | 1회 | 공감 표현으로 질문 차감을 피할 수 없음 |
| 서로 독립적인 질문이 여러 개 포함된 발언 | 접수 전 분리 안내 | 한 번에 질문 하나씩 보내도록 요청, 답변·차감하지 않음 |
| 남은 기회가 없는 상태의 질문 | 접수하지 않음 | 여섯 번째 질문에 대한 답변을 생성하지 않음 |

복합 입력은 여러 질문을 한 번의 기회로 처리하는 우회를 막기 위해 **한 번에 한 질문**으로 안내한다. 검출된 질문에 실제 답하지 않고 입력 내용을 유지한 채 나눠 보내도록 한다. 예를 들어 “언제부터 그랬고, 그때 어떤 감정이었나요?”는 두 질문으로 나눠 보낸다. 문장 수나 물음표 개수만으로 질문 수를 확정하지 않는다.

코드는 `사용한 질문 수`를 0~5 범위로 관리한다. 유효한 질문 1개에 대한 환자 응답과 원문이 저장될 때 사용량을 함께 확정한다. 응답 대기 중에는 중복 전송을 막으며, 통신 실패·생성 오류·같은 요청 재시도는 추가 차감하지 않는다. LLM 분류 결과가 잘못된 형식이면 대화에 반영하지 않고 재시도한다.

질문이 아닌 발언의 횟수와 질문 5개 제한은 구분하되, 5개 사용 후에는 추가 대화를 계속 열어두지 않고 4절의 마무리 절차로 넘어간다. 재상담에서는 기억을 이어받고 질문 기회만 새로 5개 부여한다.

### 3.3 실제 게임의 질문 사용량 표시 `[확정]`

실제 게임에는 질문 5개 중 몇 개를 사용했는지 바와 숫자로 표시한다. 화면의 기존 `주질문` 표기는 모두 `질문`으로 바꾼다.

```text
질문 사용 2/5   [■][■][□][□][□]   남은 질문 3개
최근 처리: 질문 1개 사용 · 후속질문도 횟수에 포함됩니다
```

- 응답·원문 저장 확정 후 칸과 숫자를 함께 갱신한다. 분류 중에는 미리 차감하지 않는다.
- 질문이 없는 인사·공감은 `질문 사용 없음`으로 안내한다.
- 복합 질문에는 `질문을 하나씩 나누어 보내주세요`를 표시한다.
- 4/5에서는 `질문이 1개 남았습니다`를 안내한다.
- 5/5에서는 `질문을 모두 사용했습니다 · 상담을 마무리합니다`로 바꾸고 새 대화 입력을 막는다.
- 바는 상담 점수가 아니라 사용한 질문 수다. 책 안내서 열람·페이지 넘김·기록부 열람은 횟수에 영향을 주지 않는다.

## 4. 다섯 번째 답변 이후 상담 종료

### 4.1 마무리 순서 `[구체화 제안]`

1. 다섯 번째 질문에 대한 환자의 답변을 끝까지 제공한다.
2. 새 질문 전송을 막고, LLM이 이번 상담을 짧게 정리하는 마무리 응답을 생성한다. 다섯 번째 답변과 정리는 한 응답에 함께 구성할 수 있다.
3. 미해결 내용은 다음 상담의 기억으로 남긴다. 남은 고민이 있다는 이유로 이번 회차에 여섯 번째 질문을 허용하지 않는다.
4. 마무리 발화는 새로운 질문이나 플레이어 답변을 요구하지 않는다. 기존의 다섯 번째 답변 이후 추가 발언 보장·무제한 후속 대화·종료 가능 여부 반복 판정은 이 흐름으로 대체한다.
5. **마무리까지 포함한 원문을 먼저 저장**하고, 저장 성공 후 두 축 평가를 자동 호출한다.
6. 검증된 평가 결과·클리어 여부·보상 정산을 함께 자동 저장하고 결과 화면을 보여준다.

종료 여부는 LLM이 기회를 늘려 결정하지 않는다. 코드는 유효한 질문 5개와 응답 완료를 확인하고, LLM은 그 범위에서 자연스러운 마무리 내용을 작성한다.

```text
마무리 진입 = 질문 사용량 5/5 AND 다섯 번째 답변 완료
평가 호출 가능 = 마무리 대화 완료 AND 종료 원문 저장 성공
```

### 4.2 중단과 실패 처리

- 5개를 사용하기 전에 게임을 닫으면 같은 회차의 사용량·기억을 자동 저장해 이어간다. 중단을 상담 클리어나 실패로 판정하지 않는다.
- 마지막 답변·마무리 생성 중 실패하면 같은 요청에서 재시도한다. 새 질문 기회를 차감하지 않는다.
- 5/5에서 마무리·저장이 미완료된 경우 이어하기는 해당 처리부터 복원한다. 질문 입력은 다시 열지 않는다.
- 원문 저장이 실패하면 평가를 호출하지 않는다. 유효 평가가 확정된 회차는 그 결과를 재사용해 완료 인원·보상이 중복되지 않게 한다.

## 5. 서윤 평가와 클리어 조건

### 5.1 서로 독립적인 두 평가축 `[확정]`

**서윤의 변화 100점**, **상담자의 대응 100점**을 각각 평가한다. 두 축은 각 25점짜리 4개 항목으로 구성하며, 합산·평균 점수로 통과시키지 않는다.

| 평가축 | 항목 | 평가 내용 | 배점 |
| --- | --- | --- | ---: |
| 서윤의 변화 | A1. 자기 가치 분리 | 취업 결과·타인과의 비교를 자신의 전체 가치와 구분하는 표현 | 25 |
| 서윤의 변화 | A2. 질투와 회피 감정 인정 | 질투·회피 감정을 자신의 말로 인식하고 인정하는 표현 | 25 |
| 서윤의 변화 | A3. 카페 능력 인정 | 자신이 가진 카페 관련 능력과 경험의 가치를 인정하는 표현 | 25 |
| 서윤의 변화 | A4. 현실적인 선택과 휴식 계획 | 자신의 상황에 맞는 선택과 구체적인 휴식 계획을 표현 | 25 |
| 상담자의 대응 | B1. 공감 | 서윤의 감정을 인정하고 경청하는 대응 | 25 |
| 상담자의 대응 | B2. 단정하지 않는 탐색 | 해석을 강요하지 않고 질문으로 맥락을 탐색하는 대응 | 25 |
| 상담자의 대응 | B3. 선택 존중 | 서윤의 선택권과 속도를 존중하는 대응 | 25 |
| 상담자의 대응 | B4. 경제 및 구직 현실 고려 | 경제적 조건과 구직 현실을 고려한 대응 | 25 |

```text
서윤 변화 점수 A = A1 + A2 + A3 + A4        # 0~100
상담자 대응 점수 B = B1 + B2 + B3 + B4      # 0~100
클리어 = 다섯 번째 답변·마무리 및 원문 저장 완료
      AND 유효한 평가 수신
      AND A >= 70
      AND B >= 70
```

| 서윤 변화 | 상담자 대응 | 결과 |
| ---: | ---: | --- |
| 70 | 70 | 클리어 |
| 90 | 60 | 미클리어 · 지속적인 상담 필요 |
| 60 | 90 | 미클리어 · 지속적인 상담 필요 |
| 69 | 100 | 미클리어 · 지속적인 상담 필요 |

점수는 게임 내 상담 목표에 대한 평가다. 외부 행동의 실행이나 모든 비밀 정보 공개를 별도 필수 조건으로 추가하지 않는다. 다른 환자의 변화 항목은 해당 인물의 각색 스토리에 맞게 별도 작성하며, 서윤의 항목을 모든 환자에게 복사하지 않는다. `[제안]` 다른 환자도 두 축 각각 100점·각각 70점 기준은 동일하게 적용한다.

### 5.2 평가에 사용하는 기록 `[확정]`

| 평가축 | 기록 범위 | 원칙 |
| --- | --- | --- |
| 서윤의 변화 | 이전 상담을 포함한 이번 회차까지의 누적 기록 | 누적된 자기 이해·감정 인정·선택의 변화를 평가 |
| 상담자의 대응 | 이번 상담 회차의 상담자 발언 | 이전 상담에서 잘했던 대응으로 이번 회차 점수를 보충하지 않음 |

- 긴 기록은 **모든 구간**에서 실제 발언의 지지 근거와 반대 근거를 추출한다. 최근 몇 턴이나 긍정적인 문장만으로 판정하지 않는다.
- 누적 기록을 구간별로 처리하더라도 각 근거에 회차·발언 위치를 남겨 원문을 확인할 수 있게 한다. `[제안]`
- 서윤의 발언에 상반된 근거가 있으면 발언 시점과 맥락을 함께 보고 평가한다. 이전 점수를 단순 가산하거나 과거 최고점만 고르지 않는다.
- 상담자 대응을 해석하기 위한 이번 회차의 환자 발언은 함께 참고할 수 있으나, 채점 대상은 이번 회차 상담자의 대응이다.
- 대화용 기억 요약과 평가용 전체 원문 검토를 구분한다. 요약에서 빠졌다는 이유로 평가 근거를 누락하지 않는다.

### 5.3 평가 처리와 결과 표시

`[제안]` LLM은 8개 항목의 점수와 지지·반대 근거를 반환한다. 코드는 각 항목이 0~25 범위인지, 항목 누락·중복이 없는지, 근거가 올바른 환자·실험·회차를 참조하는지 확인하고 두 축의 점수와 클리어 여부를 계산한다. 세부 채점 예시는 별도 평가 가이드로 관리한다.

결과 화면은 두 축을 각각 `서윤의 변화 00/100`, `상담자의 대응 00/100`으로 보여주고, 각 축의 70점 기준과 항목별 이유를 표시한다. 한 축이 미달하면 보완할 점을 안내한다. 잘못된 평가 응답은 0점이나 미클리어로 처리하지 않고 평가 대기로 유지한다.

## 6. 기억, 요약, 이후 대화의 변화

### 6.1 상담 중 기억 관리 `[확정]`

- 상담 도중에도 모델 입력이 **약 12,000토큰에 가까워지면** 오래된 대화 내용을 요약한다. 방문 종료 시점에만 요약하지 않는다.
- 최근 **약 6왕복**은 원문으로 유지하고, 더 오래된 구간을 요약과 함께 연결한다. 왕복은 상담자 발언과 환자 응답 한 쌍을 뜻한다.
- **입력과 출력의 합을 16,384토큰 이내**로 관리한다. 시스템 설정·고정 환자 정보·기억·최근 대화 등 전체 입력과 출력 예산을 함께 계산한다.
- 전체 상담 원문은 별도로 보존한다. 요약은 모델에 전달하는 입력을 줄이는 수단이며 원문 삭제가 아니다.
- 재상담에서도 고정 설정, 누적 요약, 최근 대화, 미해결·이월 주제와 현재 상태를 이어받는다.

`[제안]` 출력 공간을 먼저 확보하고, 입력이 길면 오래된 요약·부가 입력부터 줄여 최근 약 6왕복 원문을 유지한다. 그래도 16,384 상한을 충족하지 못하면 한도를 넘겨 호출하거나 최근 기록을 조용히 누락하지 않고, 입력 길이 조정이 필요한 상태를 안내한다. 요약 호출과 긴 기록 평가 호출도 각각 같은 예산을 준수한다. 관련 과거 원문을 검색해 가져오는 기능은 **추가 제안**으로, 현재 확정된 요약 방식과 구분한다.

### 6.2 상담사 발언에 따라 바뀌는 다음 내용 `[확정]`

- 상담사의 질문·공감·해석·제안에 따라 환자의 다음 반응, 공개 정보, 자기 이해, 동의하는 선택과 다음 상담의 화제가 달라진다.
- 같은 환자라도 이전 회차의 실제 대화와 현재 상태를 반영하며, 고정된 대사 순서를 그대로 재생하지 않는다.
- 다음 상담은 이전에 합의한 목표나 남은 갈등을 이어간다. 이후 내용의 변화는 고정 인물 설정과 확인된 사실의 범위 안에서 만든다.
- **계획·의향·약속과 실제 실행 사실을 구분한다.** “해보고 싶다”는 발언을 “이미 실행했고 좋은 결과가 있었다”로 바꾸지 않는다.
- 자기 이해와 구체적인 선택을 자신의 말로 표현한 것만으로도 변화의 근거를 인정한다. 상담 밖 사건의 발생을 클리어에 강제하지 않는다.

예: 서윤이 “친구에게 마음을 말해보고 싶어요”라고 했다면, 다음 상담에서 “지난번에 이야기했던 마음을 어떻게 표현할지 더 생각해보고 싶어요”처럼 맥락을 이어갈 수 있다. 그러나 실제로 연락했고 친구가 좋은 반응을 보였다는 사건을 자동 생성하지 않는다.

`[제안]` 기록은 `확인된 사실`, `현재 감정·해석`, `계획·선택`, `실행 확인`, `미해결 주제`로 나눈다. 상담 밖 사건을 분기로 추가하려면 각색 시나리오의 명시된 발생 조건과 확정 절차를 따로 마련한다. LLM이 스스로 생성한 회상만으로 실행 사실을 확정하지 않는다.

## 7. 환자 구성, 서윤 고정 설정, 자격증

### 7.1 총 6명과 단계별 구성 `[확정]`

- 총 환자 수는 **6명**으로 확정한다.
- **초급 단계 2명, 중급 단계 2명, 상급 단계 2명**으로 구성한다.
- 단계가 높아져도 더 어려운 환자를 배정하지 않는다. 모든 환자의 상담 부담은 비슷하게 유지하고 인물의 사연·성격·말투·관계로 차별화한다.
- 서윤 외 환자의 세부 설정은 팀에서 각색한 실제 콘텐츠로 채운다. 이 문서에서 이름·신상·사연을 임의 생성하지 않는다.

| 자격증 | 승급 조건 `[제안]` | 해당 단계 환자 수 `[확정]` |
| --- | --- | ---: |
| 초급 | 게임 시작 | 2명 |
| 중급 | 서로 다른 환자 누적 2명 완료 | 2명 |
| 상급 | 서로 다른 환자 누적 4명 완료 | 2명 |

승급 기준이 누적 완료 인원이라는 원칙은 확정이다. 위의 2명·4명 기준은 단계별 2명 구성에 맞춘 구체화 제안이다. 동일 환자의 재방문·평가 재시도·저장 복원은 완료 인원을 추가하지 않는다. `[제안]` 승급 시 해당 단계의 새 환자를 공개하고 자격증을 갱신한다.

### 7.2 서윤의 고정 설정 `[확정]`

| 구분 | 규칙 |
| --- | --- |
| 이름 | 서윤 |
| 나이·성별·지원 직무 | 제공되지 않은 주요 정보는 임의로 정하지 않음 |
| 말투 | 존댓말 |
| 응답 길이 | 2~4문장 |
| 표현 | 행동 묘사 제외, 환자의 발화로 응답 |
| 사건 시점 | 친구의 합격 사건은 첫 상담 이전에 이미 발생 |
| 변화 평가 | 자기 가치 분리, 질투·회피 감정 인정, 카페 능력 인정, 현실적인 선택·휴식 계획 |

친구의 합격을 재상담 사이에 새로 발생한 사건으로 바꾸지 않는다. 카페 능력 평가 항목이 있다는 이유로 제공되지 않은 직업·지원 직무·근무 이력을 추가하지 않는다. 실제 각색 원본에 있는 설정을 기준으로 한다.

### 7.3 환자 데이터 작성 기준 `[제안]`

환자마다 고유 ID, 제공된 고정 설정, 말투, 사건 시점, 각색 사연, 공개 조건, 변화 평가 항목, 상담자 대응 가이드, 계획과 사실의 구분, 방문 단계, 미해결 주제를 연결한다. 알려지지 않은 정보와 숨겨진 정보를 별도로 표시하며, 다른 환자의 기억을 섞지 않는다.

### 7.4 점수 기반 재화 `[확정 기능·금액은 설계안]`

재화 명칭은 **코인(C)**, 시작 잔액은 **0C**다. LLM이 제안한 항목별 평가를 코드가 검증한 뒤, **Unity가 고정 환산식으로 금액을 계산·지급**한다. LLM이 보상액을 임의로 생성하지 않는다.

두 평가축을 동등하게 반영한다. 한 축이 70점 미만이면 미클리어지만 유효하게 종료·평가한 상담에는 기본 보상을 인정한다. 최초 클리어에는 100C를 추가 지급한다.

```text
A = 이번 평가의 환자 변화 점수 (0~100)
B = 이번 평가의 상담자 대응 점수 (0~100)
보상 환산점수 S = (A + B) / 2
현재 기본 보상 기준 R = floor(S × 2) = floor(A + B)    # 0~200C
H = 이 환자에게 이미 인정·지급한 최고 기본 보상 기준 (최초 0)
이번 기본 지급액 = max(0, R - H)
최초 클리어 보너스 = 100C, 단 두 축 모두 70점 이상이고 아직 지급하지 않았을 때만
이번 총 지급액 = 이번 기본 지급액 + 최초 클리어 보너스
정산 후 H = max(H, R)
```

소수점은 마지막 코인 환산에서만 버린다. 클리어 판정에는 반올림하지 않은 원래 두 축 점수를 사용한다. H는 지갑 잔액이 아니므로 아이템을 구매해도 줄어들지 않는다. 보상용 평균 점수는 클리어 판정을 대신하지 않는다.

**첫 평가 기준 예시**:

| 환자 변화 A | 상담자 대응 B | 환산점수 S | 기본 보상 | 최초 클리어 보너스 | 총 획득 | 결과 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 50 | 50 | 50 | 100C | 0C | 100C | 미클리어 |
| 90 | 60 | 75 | 150C | 0C | 150C | 미클리어 |
| 70 | 70 | 70 | 140C | 100C | 240C | 클리어 |
| 80 | 80 | 80 | 160C | 100C | 260C | 클리어 |
| 90 | 90 | 90 | 180C | 100C | 280C | 클리어 |
| 100 | 100 | 100 | 200C | 100C | 300C | 클리어 |

같은 클리어 조건 안에서는 환산점수가 높을수록 기본 보상 기준이 높아진다. 클리어 보너스는 별도이므로 평균 75점의 미클리어보다 평균 70점의 클리어가 더 많은 총 보상을 받을 수 있다.

**재상담은 최고 기본 보상보다 오른 차액만 지급**한다. 같은 점수·낮아진 점수를 반복해 코인을 계속 받지 않도록 한다. 예를 들어 첫 상담 60/60에서 120C를 받고, 재상담 80/80으로 클리어하면 `160 - 120 + 100 = 140C`를 추가 지급해 누적 260C가 된다. 처음부터 80/80으로 완료한 경우와 같다. 90/60으로 150C를 받은 뒤 70/70으로 완료하면 기본 추가 지급은 0C지만 최초 클리어 100C는 지급한다.

- 환자 한 명의 누적 보상 상한은 300C, 6명 전체의 이론상 상한은 1,800C다. 보장 금액이 아니며 환자 단계에 따른 배율은 없다.
- 평가 실패·중단·미완료 대화에는 지급하지 않는다. 이미 정산된 회차는 저장된 평가·정산 결과를 재사용한다.
- 회차별 정산 ID, 환자별 H, 최초 클리어 보너스 지급 여부를 저장해 재전송·불러오기·중복 결과로 재지급하지 않는다.
- 새 실험·새 게임은 별도 지갑으로 시작하고 이전 실험의 돈·상품을 가져오지 않는다. 이전 기록과 보유 내역은 그 실험에 보존한다.
- 완료 환자 재도전 기능은 이번 상점 복원을 위해 추가하지 않는다. 낮은 점수로 완료한 환자의 보상을 나중에 올릴 수 있다고 안내하지 않는다.

결과 화면 하단에 환산점수, 이번 기본 지급액, 최초 클리어 보너스, 총 획득 코인과 잔액을 별도로 표시한다. 추가 지급이 없으면 `이전 최고 기록 보상 지급 완료`를 안내한다.

### 7.5 치장 전용 상점과 가격 `[확정 기능·상품과 가격은 설계안]`

모니터에서 상점을 연다. 아이템은 외형만 바꾸며 점수, 질문 수, 정보 공개, 환자 반응, 자격증 조건에는 영향을 주지 않는다. 힌트·비밀 정보·추가 질문 기회는 판매하지 않는다.

| 아이템 | 슬롯 | 외형 변화 | 가격 |
| --- | --- | --- | ---: |
| 파스텔 펜 세트 | 필기구 | 책상 위 필기구 색과 모양 | 100C |
| 패턴 머그컵 | 머그컵 | 책상 위 장식용 컵 | 150C |
| 작은 화분 | 화분 | 책상 한쪽의 식물 장식 | 200C |
| 빈티지 스탠드 | 조명 | 조명 외형·은은한 분위기, 대화 가독성 유지 | 300C |
| 패브릭 의자 | 의자 | 화면에서 보이는 의자 외형 | 400C |
| 월넛 책상 스킨 | 책상 | 책상 표면의 색·질감 | 500C |
| **전체 상품 합계** | | | **1,650C** |

기본 외형은 무료로 제공한다. 장식이 없는 슬롯은 기본 상태가 공백일 수 있다. 상품은 1회 구매로 영구 보유하고, 슬롯마다 기본 외형 또는 보유 상품 하나를 장착한다. 장착·해제는 무료이며 여러 슬롯은 동시에 꾸밀 수 있다. 환불·판매·소모성 아이템·현금 결제는 도입하지 않는다.

**가격 기준**: 첫 클리어 240~300C로 저가 상품 1~2개를 선택할 수 있고, 400~500C 상품은 보통 클리어 2회 정도 모아 구매한다. 6명 모두 70/70으로 첫 클리어하면 총 1,440C이므로 모든 상품을 사지는 못한다. 모두 90/90으로 완료하면 1,680C로 전체 상품을 살 수 있다. 전 상품 수집은 한 진행에서 보장되지 않는 선택 목표이며, 엔딩에는 어떤 구매도 요구하지 않는다. 금액은 6명 플레이를 가정한 초기 밸런스로 실제 플레이 검증 후 조정한다.

**구매·장착 흐름**: 잔액·가격·미리보기 확인 → 구매 → 잔액 차감과 소유권을 함께 확정·자동 저장 → 장착 → 외형과 장착 상태 자동 저장. 보유 상품은 재구매 대신 장착 버튼을 표시한다. 잔액 부족·저장 실패 시 구매를 확정하지 않으며, 중복 입력은 한 번만 처리한다.

`[구현 연결 제안]` 현재 상담실 배경은 한 장의 이미지이므로 배경 변형 또는 장식 레이어를 별도로 준비해야 한다. 특히 의자는 실제 화면에서 보이도록 표시 영역을 먼저 정한다. UI 글자 대비, 기록부 클릭 영역, 모달 블러와 빈 기록부 사진 칸은 유지한다. 이번 문서는 상품과 규칙을 정한 것이며 해당 에셋·상점 기능 구현 완료를 의미하지 않는다.

## 8. 기록부와 상담실 UI

### 8.1 기록부 `[별도 화면 요구사항]`

책상 위 서류 파일을 누르면 첨부 이미지의 클립보드형 기록부를 연다. **사진 칸은 항상 공백**으로 유지한다. 기본 정보, 내원 사유, 심리 상태·성격, 과거 이력, 회차별 상담 기록, 담당자를 표시한다. 제공된 심화 정보는 처음에는 가리고 대화를 통해 항목별로 공개한다.

| 정보 상태 | 표시 원칙 |
| --- | --- |
| 미설정·미확인 | 제공되지 않았거나 사실 여부를 확인하지 못한 정보. 추정해 채우지 않음 |
| 해당 없음 | 실제로 해당하지 않는다고 확인된 경우만 사용 |
| 설정되어 있으나 미공개 | 내용은 존재하며 공개 조건 충족 전 블러 처리 |
| 공개됨 | 조건 충족 후 확인된 정보를 표시 |

`[기존 방향]` LLM이 공개 후보를 제안하고 Unity가 조건을 확인하여 공개한다. `[제안]` 미공개 실제 문장을 툴팁·복사 등으로 읽을 수 없도록 가림용 표시를 사용한다. 공개된 정보는 재상담에서도 유지하고, 새 실험에서는 초기 공개 상태로 되돌린다.

### 8.2 화면 구성과 모니터

| 요소 | 기능 | 구분 |
| --- | --- | --- |
| 환자·대화창 | 자유 입력, 환자 발화, 대화 기록 | 확정 핵심 기능 |
| 질문 사용량 바 | 0/5~5/5, 남은 질문, 소진 후 마무리 안내 | 총 질문 5개 기준 |
| 우측 상단 책 아이콘 | 클릭 시 확대 안내서, 이전·다음 페이지·닫기 | 신규 화면 요구사항, 아직 미구현 |
| 서류 파일 | 환자 상세 기록, 빈 사진 칸 | 기존 별도 화면 요구사항 |
| 모니터 | 치장 상점·내 프로필·자격증·현재 상태·사진 폴더 진입 | 상점 복원 및 기존 화면 요구사항 |

| 사진 폴더의 내용 | 스토리 이벤트 이미지 열람 | 콘텐츠·획득 조건은 추가 제안 |
| 설정 | 한 화면 위쪽 그래픽·아래쪽 오디오, 시작 화면에서 진입 | 시작 화면 요구 확정, 상세 항목은 8.4절 설계안 |

모니터의 현재 상태에는 코인 잔액, 완료 인원, 전체 진행도, 현재 환자, 재상담 대기 상태를 표시한다. 사진 폴더와 기록부 사진 칸은 별개이며, 사진 폴더에 이미지가 생겨도 기록부 사진 칸은 계속 공백이다. 기록부·모니터를 열고 닫아도 진행 중인 대화와 사용량을 유지한다. `[제안]`

### 8.3 우측 상단 책 형태의 게임 안내서

`[확정]` 인게임 화면 **우측 상단에 책 모양 아이콘**을 배치한다. 플레이어가 클릭하면 책이 확대되어 안내서가 열리고, 페이지를 넘기며 게임의 기본 흐름을 익힐 수 있다.

#### 열기·페이지 넘기기·닫기 `[구체화 제안]`

- 책 아이콘에 `게임 안내` 이름과 툴팁을 제공한다. 질문 사용량 바·설정 버튼과 겹치지 않게 배치한다.
- 클릭하면 중앙에 큰 책 형태의 창이 열리고 배경을 어둡게 해 본문을 읽기 쉽게 한다. 짧은 확대·페이지 전환 효과를 사용한다.
- 책 좌우에 `이전`·`다음` 버튼, 하단에 `현재 페이지 / 전체 페이지`를 표시한다. 첫 페이지의 이전·마지막 페이지의 다음 버튼은 비활성화한다.
- 오른쪽 위 닫기 버튼 또는 Esc로 닫는다. 책에 초점이 있을 때만 좌우 방향키로 페이지를 넘긴다.
- 처음 열면 1쪽부터, 이후에는 현재 플레이 중 마지막으로 읽은 쪽부터 연다. 페이지 위치의 재실행 후 복원은 필수 기능으로 두지 않는다.
- 읽기는 선택 사항이며 전 페이지 열람을 상담 시작·클리어·엔딩 조건으로 강제하지 않는다. 첫 게임에는 아이콘을 짧게 강조해 안내서 위치를 알려준다.

#### 페이지 구성 `[콘텐츠 제안: 총 6쪽]`

| 쪽 | 제목 | 안내 내용 |
| ---: | --- | --- |
| 1 | 상담사의 하루 | 환자 선택 → 대화 → 기록 확인 → 평가 → 재상담 또는 완료, 6명 완료와 자격증 성장 |
| 2 | 질문은 총 5개 | 주질문·후속질문 모두 1개씩 사용, 한 번에 한 질문, 0/5~5/5 바, 다섯 번째 답변 후 마무리·자동 평가 |
| 3 | 기록부 읽기 | 서류 클릭, 기본 정보와 대화로 공개되는 심화 정보, 미확인과 해당 없음의 차이, 사진 칸 공백 |
| 4 | 평가와 재상담 | 환자 변화·상담자 대응 각각 100점, 두 점수 모두 70점 이상 완료, 90/60은 미클리어, 재상담은 기억 유지·질문 5개 갱신 |
| 5 | 코인으로 꾸미기 | 두 점수 평균 × 2의 기본 기준, 재상담 최고 보상 차액, 최초 클리어 100C, 모니터의 치장 전용 상점 |
| 6 | 저장과 다시 시작 | 자동 저장, 중단 후 이어하기는 사용량 유지, 재상담·새 실험의 차이, 다시 책을 여는 방법 |

각 쪽은 짧은 문장과 간단한 화면 그림으로 구성한다. 환자의 비밀 설정, 평가의 정답 대사, 미공개 사연을 안내서에 노출하지 않는다. 2쪽에는 `왜 그렇게 느꼈나요?` 같은 후속질문도 1개를 사용한다는 예시를 넣어 이전 규칙과 혼동하지 않게 한다.

#### 상담 중 열람과 상태 보존 `[구체화 제안]`

- 책을 열거나 페이지를 넘겨도 질문 수·점수·재화가 바뀌지 않는다.
- 책이 열린 동안 뒤쪽 질문 입력·환자 선택·상점 구매 클릭을 막는다. 기록부 등 다른 모달과 동시에 겹쳐 열리지 않도록 한다.
- 현재 입력 초안, 질문 사용량, 대화 위치를 유지하고 닫으면 기존 상담으로 복귀한다. 책 안의 화살표 입력이 상담 입력창에 전달되지 않게 한다.
- 이미 전송한 응답 요청은 책을 열었다고 취소·재전송하지 않는다. 완료된 응답은 한 번만 저장하고, 책 뒤에서 질문 차감이 중복되지 않도록 한다.
- 대화 타이핑과 다음 화면 전환은 열람 중 보류한다. 서버 응답·자동 저장은 완료할 수 있으며, 책을 닫으면 확정 상태를 표시한 뒤 진행한다. 마지막 응답이라면 결과 화면 전환도 닫은 뒤 이어간다.
- 책은 고정 위치를 유지하되 해상도별 안전 여백과 글자 크기를 검증한다. 페이지 넘김을 반복해도 내용을 건너뛰거나 다른 화면을 클릭하지 않게 한다.

### 8.4 시작 화면과 설정 화면

`[확정]` 사용자 제공 상담실 배경과 비슷한 분위기로 시작 화면을 구성한다. 메뉴는 위에서부터 **새 게임 → 불러오기 → 설정 → 게임 종료** 네 가지다. `불러오기`는 저장 슬롯 선택이 아니라 **마지막으로 확정된 자동 저장에서 이어하기**를 뜻한다. 설정은 그래픽과 오디오를 탭으로 나누지 않고 **한 페이지 위쪽에 그래픽, 아래쪽에 오디오**를 배치한다.

#### 시작 화면 배치 `[설계안]`

- 기존 상담실 그림의 비율을 유지하고 왼쪽에 짙은 갈색에서 투명해지는 그라데이션을 겹친다. 문이 있는 왼쪽 약 40%를 제목·메뉴 영역으로 활용하고 오른쪽 창문과 모니터는 보이게 둔다.
- 가제 `상담 커피톡`은 왼쪽 상단, 네 메뉴는 그 아래 세로로 정렬한다. 크림색 글자, 올리브색 선택 표시, 얇은 구분선으로 기존 배경의 따뜻한 색감을 유지한다.
- 기본 선택은 새 게임이며 선택·마우스 올림 상태는 밝기와 표시 모양으로 함께 구분한다. 글자는 배경 이미지에 합치지 않고 UI 텍스트로 만든다.
- 저장이 없을 때 불러오기를 비활성화하고 `저장된 진행이 없습니다`를 가까이 표시한다. 실제 저장을 연결하면 최근 저장 시각과 현재 환자·진행 위치를 짧게 표시한다. 허구의 저장 정보를 실제 플레이 기록처럼 보여주지 않는다.
- 16:9를 기준으로 배치하되 다른 화면 비율에서도 메뉴와 설정 조작이 잘리지 않게 배치한다. 배경은 비율을 유지한 채 화면을 채워 일부 가장자리가 잘릴 수 있다. 설정 화면의 짧은 세로 공간에서는 같은 페이지 안에서 스크롤하며 그래픽·오디오 탭을 새로 만들지 않는다.

| 메뉴 | 실제 게임에서의 목표 동작 | 예외와 편의 처리 |
| --- | --- | --- |
| 새 게임 | 별도 진행 ID에서 초기 상태로 시작하고 상담실로 이동 | 기존 진행이 있으면 새로 시작 여부 확인. 기존 상담 원문·이력은 보존하며 취소 시 아무 상태도 바꾸지 않음 |
| 불러오기 | 마지막 정상 자동 저장의 같은 회차·질문 사용량·공개 상태·처리 단계 복원 | 저장 없음은 비활성. 손상·버전 불일치는 오류를 알리고 초기 상태로 덮어쓰지 않음. 로딩 중 중복 클릭 차단 |
| 설정 | 그래픽 위·오디오 아래의 한 페이지 열기 | 배경 메뉴 입력 차단, 취소·Esc로 마지막 적용값 복원 후 닫기 |
| 게임 종료 | 종료 확인 후 앱 종료 | 기본 초점은 취소. 저장 처리 중이면 완료·실패 상태를 먼저 확인하며 저장 성공을 허위 표시하지 않음 |

새 게임은 기존 9.2절의 별도 진행·기록 보존 방향을 따른다. 불러오기는 재상담과 달리 질문 수를 5개로 다시 채우지 않으며, 5/5 마무리·평가 대기 상태도 복원한다. 완료 인원·보상은 불러오기만으로 다시 지급하지 않는다. 이번 요청에 수동 저장·여러 슬롯·클라우드 저장은 추가하지 않는다.

설정의 적용값과 편집 중 값을 분리한다. 게임 진행을 새로 시작해도 사용자 설정은 유지한다. 전체 음량 0은 BGM·효과음 모두 음소거하며, 개별 음량은 전체 음량과 함께 적용한다. 실제 음원과 오디오 출력 연결은 후속 Unity 작업이다. 화면 모드·해상도의 실제 적용 시 화면을 확인하고 되돌릴 수 있는 짧은 복구 절차를 권장한다. 텍스트 속도 등 추가 항목은 이번 화면 범위에 넣지 않는다.

마우스와 Tab·Enter·Esc로 조작하고 초점을 눈에 보이게 표시한다. 모달이 열려 있는 동안 뒤 메뉴가 눌리지 않아야 하며, 닫으면 열었던 버튼으로 초점을 되돌린다. 해커톤에서는 시작 메뉴·이어하기 진입·설정 한 페이지를 먼저 연결하고 추가 전환 효과는 우선하지 않는다.

**현재 산출물 범위:** `tools/ui-preview/start-menu/index.html`의 독립 실행형 화면 시안이다. 실제 Unity 씬·저장·불러오기·그래픽 장치·음원·프로그램 종료 기능을 구현한 것으로 보지 않는다. 설정 선택의 적용·취소와 미리보기용 로컬 보존만 시연하며, 새 게임과 종료는 확인 흐름으로 표시한다. 실제 연결 지점과 검증은 15절·17절에 기록한다.

### 8.5 모니터 PC와 제공 에셋 적용

`[확정·로컬 구현]` 상담실 모니터를 누르면 배경 블러·딤·0.2초 전환을 사용해 PC 바탕화면을 중앙에 연다. PC는 실제 상담실 너비의 **82% 이내**, 좌우 9%·상하 8% 안전 여백을 유지한다. 상점·프로필·사진·환경설정은 이 PC 내부의 개별 창이다.

- 상점·프로필·사진·설정의 X와 `Esc`는 PC 바탕화면으로 돌아온다. 설정의 드롭다운이 열렸으면 드롭다운부터 닫는다. 바탕화면에서 다음 `Esc`는 상담실로 돌아간다. PC X는 내부 창과 PC를 함께 닫는다. 바깥 클릭도 가장 안쪽 창부터 닫는다.
- 기록부와 PC는 동시에 표시하지 않는다. 닫힘 전환이 끝날 때까지 상담실 클릭을 차단하고 원래 버튼으로 초점을 복원한다. PC 재열기는 바탕화면에서 시작하며 상점 기본 탭은 창문이다.
- 상점 5개 탭은 창문·문·서류철·PC·PC 배경화면이다. 원본 카탈로그의 각 8종, 총 40종을 썸네일·이름이 있는 동적 카드로 표시한다. 카드를 누르면 해당 외형과 `미리보기 중` 표시를 적용하며 `기본 복원`은 현재 분류만 되돌린다. 상점을 다시 열면 창문 탭부터 시작하지만 각 분류의 선택은 같은 Play 실행 동안 유지한다.
- 카드에는 `미정`, 하단에는 `미리보기 · 가격 미정`, 잔액에는 `— C`를 표시한다. 새 원본 `catalog.json`의 `price_krw`는 40종 모두 `null`이며 무료·0원·구매 가능으로 해석하지 않는다. 원본 통화 `KRW`와 PNG의 `원`은 보존하고 화면에만 기존 게임 단위 C를 덧씌운다. 통화 환산·구매·소유권·지갑 연결은 없다. **7.5절의 6상품 가격표는 이전 설계안이며 새 40종에 가격을 부여한 표가 아니다.**
- 창문 치장을 처음 선택하면 원본 미리보기와 같은 블라인드 절반 상태를 적용한다. 창문 탭의 `올림 / 절반 / 내림`은 선택한 테마의 정적 상태 이미지를 바꾸며 다른 테마로 바꾸어도 현재 단계를 유지한다. 기본 창문에는 조절 기능이 없어 버튼을 비활성화한다. 날씨를 바꿔도 테마·블라인드 단계는 유지하며, 내림 상태에서는 제공된 이미지처럼 바깥 날씨가 가려진다.
- 서류철 선택은 책상 위 서류철·펜과 확대 기록부의 외형을 함께 바꾼다. 기록 내용 12개 필드와 빈 사진 칸은 보존한다. 미리보기는 PC 닫기·재열기 동안 유지되고 Play 종료 후 다음 실행에서는 초기화된다. 구매·보유·재화·게임 진행 저장을 변경하지 않는다.
- 프로필에는 남녀 시각 아바타 2종과 이름·소속·한 줄 소개를 표시한다. 기본 그림은 여성 변형이며 실제 사용자나 환자의 성별을 추정하는 값이 아니다. 미설정 정보는 `—`이다. 아바타 선택 화면·프로필 저장은 아직 없다.
- 사진창은 6개 슬롯을 표시한다. 원본에 박혀 있는 예시 기념사진·`1주차 완치` 문구는 불투명 UI로 가리고 슬롯을 재구성했다. 실제 지급된 사진 데이터가 없으면 빈 상태이며 엔딩·사진 획득을 임의로 처리하지 않는다.
- PC 환경설정은 새 에셋의 **왼쪽 화면 설정·오른쪽 소리 설정**을 사용한다. 8.4절 시작 화면의 상단 그래픽·하단 오디오 시안은 별도 산출물로 보존한다. PC에는 해상도·화면 모드·전체/BGM/효과음, 적용·닫기가 있으며 품질·텍스트 속도 항목은 추가하지 않는다.
- 설정 초안과 확정값은 분리한다. 적용만 로컬 설정을 저장하며 X·하단 닫기·Esc·PC 전체 닫기는 미적용 값을 버린다. 저장 설정은 새 게임 진행과 별개다. Editor에서는 실제 화면 모드·해상도를 바꾸지 않으며 실행 빌드에서 적용한다. 음원은 제공되지 않아 BGM/SFX 청감 검증은 연결 후 수행한다.

## 9. 자동 저장, 이어하기, 재상담, 새 실험

### 9.1 저장 원칙 `[확정]`

**자동 저장만 제공한다.** 다섯 번째 답변과 마무리 대화를 먼저 저장하고 이후 평가를 자동 호출한다. 현재 진행뿐 아니라 모든 대화 원문을 실험·환자·회차별로 보존한다.

| 저장 내용 | 포함 데이터 |

| 플레이어 진행 | 자격증, 완료 환자 ID 목록, 엔딩 해금·재생 완료 상태 |
| 엔딩 기록 | 환자별 후일담 사진·선택 문구·문구 종류·원문 참조·순서·데이터 버전, 중앙 크레딧 목록 버전 |

| 환자 상태 | 방문 회차, 공개 정보, 현재 감정·선택, 두 축 평가와 근거 |

`[제안]` 유효한 대화 턴과 질문 사용량·공개 상태를 함께 자동 저장한다. 요약 갱신, 종료 원문 확정, 평가·보상·승급·엔딩 반영, 구매·장착 시에도 자동 저장한다. 보상은 잔액과 정산 이력을, 구매는 잔액과 소유권을 함께 확정한다. 현재 진행 상태와 원문 이력은 분리해, 진행 상태 갱신 때문에 과거 기록이 사라지지 않게 한다.

### 9.2 세 가지 시작 방식 `[확정]`

| 동작 | 기억과 기록 | 질문 기회 |
| --- | --- | --- |
| 이어하기 | 같은 실험의 중단된 같은 회차 복원 | 사용량 유지, 초기화하지 않음 |
| 재상담 | 이전 상담 기억·공개 정보·변화 상태를 이어받는 새 회차 | 5회로 초기화 |
| 새 실험 | 기존 기록을 보관하고 별도 실험 ID에서 초기 서윤으로 시작 | 5회로 초기화 |

새 실험에서는 이전 실험의 감정 변화, 공개 상태, 평가, 완료 상태, 기억을 새 실험에 주입하지 않는다. 서윤의 고정 원본 설정에서 시작한다. 새 실험은 개발·검증 작업 흐름으로 구분하고, 실제 게임 UI에 동일한 명칭의 메뉴를 넣을지는 별도 결정한다. `[제안]` 게임의 새 게임도 기존 기록을 보관한 별도 진행으로 생성한다.

### 9.3 오류와 복원 범위 `[제안]`

- 원문·상태 저장 실패를 표시하고 재시도한다. 원문 저장이 성공하기 전에는 평가를 실행하지 않는다.
- 입력·응답 처리 도중 종료되면 마지막으로 확정 저장된 대화와 사용량을 복원한다. 미완료 요청은 확정 처리로 간주하지 않는다.
- 프로그램 재실행 후 미전송 입력 초안까지 복원하는 기능은 확정 범위에 포함하지 않는다. 별도 추가 제안으로 남긴다.
- 평가 대기 상태에서 아직 유효한 결과가 없을 때만 같은 회차 평가를 재시도한다. 유효 평가가 확정된 회차는 그 결과를 재사용하며 완료·승급·보상을 중복 반영하지 않는다.
- 임시 파일 작성 후 정상 파일로 교체하는 방식 등으로 저장 중단에 대비한다. 손상 시 기록을 삭제하거나 초기 상태로 조용히 덮어쓰지 않는다.

## 11. 확정 엔딩 크레딧과 개발 순서

### 11.1 엔딩 조건과 이야기 `[확정]`

필수 환자 **6명 모두 상담을 완료하면 행복한 후일담과 제작진 크레딧**으로 마무리한다. 현재 공개된 단계의 환자만 완료했다고 엔딩을 실행하지 않는다.

```text
엔딩 조건 = 등록된 필수 환자 수가 6명
         AND 6명의 고유 환자 ID가 모두 완료 목록에 포함됨
```

- 지금까지 상담한 환자 6명 모두가 각자의 삶에서 행복하게 지내는 모습을 보여준다. 특정 인물만 빠지거나 점수가 낮았다는 이유로 불행한 사진으로 바꾸지 않는다.
- 사진은 각자의 성격·사연과 어울리는 따뜻한 일상 후일담이다. 모두에게 취업·부·연애 같은 동일한 성공을 부여하지 않고, 스스로 선택한 삶에서 편안함과 행복을 찾은 모습을 표현한다. `[장면 구체화 제안]`
- 상담 중의 계획을 실행 사실로 단정하지 않는 규칙은 유지한다. 엔딩은 **전체 상담 완료 후 시간이 흐른 시점의 별도 후일담**으로 명시하고, 작가가 작성한 장면으로 새로운 이야기를 마무리한다. 이 장면을 과거 상담 기록·기억·점수에 실제 발생 사실처럼 역으로 추가하지 않는다.
- 치장 구매·코인 잔액·사진 수집·모든 심화 정보 공개는 엔딩 조건이 아니다. 사진에 붙일 적절한 인용문이 없어도 엔딩 진입을 막지 않는다.

### 11.2 화면 구성과 이동 방향 `[확정]`

사용자가 제공한 스케치처럼 **중앙은 만든 이들의 크레딧, 좌우는 환자들의 행복한 사진과 한 줄 문구**로 구성한다. 중앙 글과 양쪽 사진·문구 묶음은 **화면 위에서 등장해 아래로 천천히 내려간다.** 사진과 그 위 문구는 함께 움직인다.

```text
                       화면 위에서 진입
                              ↓
 [내가 이 환자에게 했던 한 줄]      만든 이들       [내가 이 환자에게 했던 한 줄]
 [행복한 환자 A의 후일담 사진]    역할 · 제작자 이름   [행복한 환자 B의 후일담 사진]
                              ↓
             다음 환자 사진과 제작진 항목이 이어짐
                              ↓
                       화면 아래로 퇴장
```

- 사진 위에 플레이어의 따뜻한 발언을 **한 줄로** 표시한다. 문구와 사진 사이의 여백을 유지하고 중앙 제작진 글을 침범하지 않는다.
- 중앙에는 게임명·팀명, 만든 이들, 역할별 제작자 이름, 도움을 준 사람들, 사용 에셋·도구·라이선스에 필요한 표기를 순서대로 배치한다. `[구성 제안]`
- 제작자 이름과 역할은 실제 팀 명단·기여 내역을 확인해 사용한다. 임의의 이름을 넣거나 참여자를 누락하지 않는다. 최종 명단·에셋 표기는 별도 제작 데이터로 관리한다.
- 좌우 사진은 인물과 행복한 일상이 읽히도록 충분한 크기로 배치한다. 배경은 중앙 글과 문구가 잘 보이는 차분한 색을 사용한다. `[표현 제안]`
- 기록부의 사진 칸은 계속 공백이다. 엔딩에 사용하는 후일담 사진은 기록부 사진 칸과 별도의 에셋·화면이다.

### 11.3 사진 배치와 크레딧 속도 `[연출 제안]`

- 6명 각각 최소 1장, 총 6장의 후일담 사진을 준비한다. 좌우 2명씩 3묶음으로 순차 등장시켜 모든 인물을 보여준다.
- 기본 배치 순서는 해당 진행의 최초 상담 순서로 정하고, 왼쪽 1·3·5번째 / 오른쪽 2·4·6번째 인물을 배치한다. 이 순서를 엔딩 준비 시 저장한다.
- 사진과 문구는 하나의 카드로 묶고 제작진 글과 같은 아래 방향으로 부드럽게 이동한다. 카드 간격을 충분히 두어 인물·문구가 서로 가리지 않게 한다.
- 전체 길이는 우선 **약 80~100초**, 한 카드의 사진과 문구를 편안하게 읽을 수 있는 시간은 **최소 10초 정도**를 목표로 한다. 실제 제작진 글 길이에 맞춰 최종 속도와 간격을 조정한다.
- 중앙 크레딧의 첫 항목부터 마지막 감사 문구까지 순서대로 보이도록 각 항목의 진입 시점을 배치한다. 일반적인 아래에서 위 스크롤을 그대로 사용하지 않는다.
- 사진은 사전에 준비한 일러스트·사진형 장면을 사용한다. 플레이 도중 즉석 이미지 생성이 엔딩 재생의 필수 조건이 되지 않게 한다.
- 부드러운 배경음과 전환을 사용하며, 마지막에는 감사 인사를 잠시 보여준 뒤 종료 메뉴로 이동한다.

### 11.4 사진 위 한 줄: 플레이어의 실제 발언

`[확정]` 한 줄 문구는 **플레이어가 해당 환자에게 실제 상담 중 했던 말 중에서** 따뜻하고 감동적인 문장·구절을 고른다. 예를 들어 “잘 될 거야”는 분위기 예시이며, 실제로 하지 않은 말을 모든 사진에 공통으로 넣지 않는다.

선정 방식 `[구체화 제안]`:

1. **현재 진행·동일 환자**의 첫 상담부터 완료까지 원문에서 `상담자/플레이어` 발언만 후보로 수집한다. 환자 대사, 다른 환자와의 상담, 새 실험 이전 기록은 제외한다.
2. LLM은 공감·격려·선택 존중이 담긴 후보와 원문 위치를 제안한다. 점수가 높았던 회차만 고집하지 않고 재상담을 포함한 실제 기록을 살핀다.
3. 코드는 후보가 원문에 그대로 존재하는지, 환자 ID·회차·발언자가 맞는지 확인한다. LLM이 새로 작성하거나 더 감동적으로 바꾼 문장을 플레이어의 발언처럼 표시하지 않는다.
4. 한 줄에 들어갈 짧은 문장을 우선 선택한다. 긴 문장은 **의미가 바뀌지 않는 연속된 원문 구절**만 후보로 사용하며, 여러 발언을 이어 붙이거나 부정 표현을 잘라 뜻을 바꾸지 않는다. 가독성 이하로 글자를 줄이기보다 더 짧은 실제 구절을 다시 고른다.
5. 실제 발언이라도 비꼼·비난·강요·맥락상 부적절한 표현은 제외한다. 전체 발언과 앞뒤 맥락을 함께 확인한다.
6. 후보 하나가 검증에 실패하면 다른 원문 후보를 다시 확인한다. **해당 환자의 전체 누적 기록을 확인해도 적절한 실제 발언이 없거나 기록이 손상된 경우에만**, 인용 표시 없이 `다시 찾은 일상` 같은 **제작진의 사진 제목**으로 대체한다. 이것은 실제 상담 발언이 없는 예외 처리이며 플레이어의 발언으로 소개하지 않는다. 사진과 행복한 후일담은 그대로 보여준다.
7. 엔딩 최초 준비 시 환자별 선택 문구·원문 참조·사진·표시 순서를 저장한다. 다시 볼 때 매번 재선정하지 않는다. LLM 연결 실패 시에는 검증된 저장 후보를 우선 사용하며, 확인 가능한 발언이 전혀 없으면 6번의 예외로 처리해 엔딩을 막지 않는다.

`[데이터 제안]` 환자 ID, 사진 ID, 표시 문구, 문구 종류(플레이어 인용/사진 제목), 원문 회차·발언 ID·구절 위치, 표시 순서, 엔딩 데이터 버전을 보관한다. 인용은 환자별 사진 바로 위에 두고 사진 제목과 구분되는 인용 부호를 사용할 수 있다. 원문 내부 식별자는 화면에 노출하지 않는다.

### 11.5 엔딩 재생·저장·다시 보기 `[구체화 제안]`

1. 마지막 환자 완료·보상·승급 결과를 먼저 자동 저장한다.
2. 6명 완료를 확인하고 사진·한 줄·중앙 제작진 목록을 준비한다. 재생용 데이터를 저장한 후 크레딧에 진입한다.
3. 재생 중 질문 입력·책·기록부·상점 등 상담실 UI를 숨기거나 비활성화한다. 엔딩을 보는 동안 상담이나 재화 정산이 추가로 발생하지 않는다.
4. 일시정지·재개와 건너뛰기를 제공한다. 건너뛰어도 상담 완료·보상·엔딩 해금은 유지된다. 자동 재생 완료와 건너뛴 상태는 별도로 저장할 수 있다.
5. 끝나면 `크레딧 다시 보기`, `상담실로 돌아가기`, `타이틀로`를 제공한다. 다시 보기는 저장된 사진·문구를 사용하고 보상을 재지급하지 않는다.
6. 게임 종료 후 다시 실행하면 자동 저장된 완료 진행에서 엔딩을 다시 볼 수 있게 한다. 재생 중간 위치 복원은 필수 범위에 넣지 않고 처음부터 다시 재생한다.
7. 엔딩 후에도 기록·보유 치장 확인과 남은 코인으로 상점 이용이 가능하다.

필요한 후일담 사진 6장과 제작진 명단은 출시 전 준비·검증 항목이다. 현재는 엔딩 방향과 규칙을 확정한 상태이며, 사진 에셋·인용 선택기·크레딧 화면이 구현된 것은 아니다.

### 11.6 개발·검증 순서 `[제안]`

1. 서윤 한 명으로 질문 여부 판별·후속질문 차감·복합 질문 분리·총 5개 상한을 검증한다.
2. 다섯 번째 답변 → 마무리 → 원문 저장 → 두 축 평가를 연결한다.
3. 긴 상담 요약, 재상담 기억, 계획과 실행 사실 구분, 새 실험 분리를 검증한다.
4. 질문 사용량 바·기록부·자동 저장을 연동하고 우측 상단 책 안내서와 페이지 넘김을 구현한다.
5. 확정된 나머지 환자 콘텐츠를 포함해 총 6명·자격증·완료 조건을 검증한다.
6. 평가 보상 정산과 자동 저장을 연결한 뒤 치장 상점·장식 레이어·구매·장착을 구현한다.
7. 6명 후일담 사진·실제 발언 추출·중앙 제작진 데이터를 준비하고, 위→아래 크레딧·저장·다시 보기를 구현한다.

## 12. 수용 기준

- [ ] 시작 화면의 네 메뉴가 새 게임·불러오기·설정·게임 종료 순서로 표시된다.
- [ ] 불러오기는 마지막 정상 자동 저장을 복원하고 저장 없음·손상·중복 클릭을 처리한다. 질문·보상을 초기화하거나 재지급하지 않는다.
- [ ] 새 게임 확인 취소 시 기존 진행을 유지하고, 새로 시작하면 별도 진행으로 생성해 이전 상담 원문을 보존한다.
- [ ] 한 설정 페이지에 상단 그래픽·하단 오디오가 있고 기본값·적용·취소·Esc의 값 반영이 일관된다.
- [ ] 실제 게임에서 그래픽·음량 적용과 재실행 후 설정 복원을 확인한다. 화면 시안의 선택값 저장과 구분한다.
- [ ] 종료 확인·모달 배경 입력 차단·키보드 초점·작은 화면 가독성을 검증한다.
- [ ] 회차마다 총 질문 5개를 제공하며 후속질문·반복 질문도 1개씩 사용한다.
- [ ] LLM이 질문 여부를 판단하고 코드가 0~5 사용량을 계산한다. 물음표 없는 답변 요구도 질문으로 센다.
- [ ] 순수 인사·공감만 0회이며, 질문이 섞이면 1회를 사용한다.
- [ ] 복합 질문은 답변·차감 전에 분리 안내하며, 한 메시지에 여러 질문을 넣어 상한을 우회하지 못한다.
- [ ] 5/5 이후에는 새 주제·후속질문 모두 접수하지 않고 남은 고민만 다음 상담 기억으로 남긴다.
- [ ] 실제 게임에 사용량 바·숫자가 표시되고 분류 확정 후 사용량과 기록이 일치한다.
- [ ] 다섯 번째 답변을 끝까지 제공하고, 추가 질문을 요구하지 않는 마무리로 넘어간다.
- [ ] 코드가 질문 5개와 마지막 응답·마무리 완료를 확인하고 원문 저장 성공 후 평가를 자동 호출한다.
- [ ] 평가축마다 25점 항목 4개이며, 두 축을 각각 100점 만점으로 표시한다.
- [ ] 70/70은 클리어, 90/60·60/90·69/100은 미클리어다.
- [ ] 서윤 변화는 누적 기록, 상담자 대응은 이번 회차 발언으로 평가한다.
- [ ] 긴 원문 전체 구간에서 지지·반대 근거를 추출하고 과거 점수를 단순 합산하지 않는다.
- [ ] 약 12,000토큰에서 요약하며 최근 약 6왕복을 유지하고 전체 원문은 별도로 보존한다.
- [ ] 모든 모델 호출의 입력·출력 예산 합이 16,384토큰을 넘지 않는다.
- [ ] 서윤의 미제공 나이·성별·지원 직무를 만들지 않으며, 미설정·미확인과 해당 없음을 구분한다.
- [ ] 서윤은 존댓말 2~4문장으로 답하고 행동 묘사를 넣지 않는다.
- [ ] 친구 합격 사건의 시점을 첫 상담 이전으로 유지한다.
- [ ] 상담자 발언이 다음 반응·선택·공개 정보에 반영되며, 계획을 실행 사실로 바꾸지 않는다.
- [ ] 이어하기는 사용량을 유지하고 재상담은 기억을 유지하면서 기회만 5회로 초기화한다.
- [ ] 새 실험은 기존 기록을 보관하고 이전 상태가 섞이지 않은 초기 서윤으로 시작한다.
- [ ] 저장은 자동으로만 수행하며 평가 재시도·복원으로 완료 인원이 중복 증가하지 않는다.
- [ ] 기록부 사진 칸은 모든 상태에서 공백이며 모니터 사진 폴더와 별개다.
- [ ] 총 6명·단계별 2명 구성을 유지하고 자격증에 따른 난이도 상승이 없다.
- [ ] 모든 필수 환자를 완료해야 엔딩으로 진행한다.
- [ ] 최초 70/70은 240C, 90/60은 미클리어·150C, 100/100은 300C를 지급한다.
- [ ] 동일 환자의 60/60 → 80/80 재상담은 120C → 추가 140C로 누적 260C이며, 보유금을 썼다고 재지급하지 않는다.
- [ ] 동일·하락 점수는 기본 추가 지급 0C이며, 최초 클리어 보너스는 별도로 1회만 지급한다.
- [ ] 평가 재요청·결과 중복·자동 저장 복원으로 돈이나 소유 상품이 늘어나지 않는다.
- [ ] 상품 가격은 100·150·200·300·400·500C, 전체 합계 1,650C이며 중복 구매와 음수 잔액을 허용하지 않는다.
- [ ] 구매·장착 상태가 자동 저장되고, 새 실험은 별도 0C·기본 외형으로 시작한다.
- [ ] 치장은 상담 판정·기회·공개 조건·엔딩에 영향을 주지 않으며 기록부 사진 칸은 공백이다.

- [ ] 우측 상단 책 아이콘을 클릭하면 확대 안내서가 열리고 6쪽을 이전·다음 버튼으로 넘길 수 있다.
- [ ] 첫·마지막 페이지 버튼 상태, 페이지 번호, 닫기 버튼·Esc·방향키가 의도대로 동작한다.
- [ ] 안내서 열람은 질문·점수·재화에 영향을 주지 않고, 닫으면 입력 초안·상담 상태로 복귀한다.
- [ ] 책 뒤의 클릭·입력은 차단하고 진행 중 응답은 한 번만 저장하며 대화 표시·화면 전환은 닫은 뒤 이어간다.
- [ ] 책의 질문·평가·코인·저장 설명이 최신 기획과 같고 미공개 환자 사연을 노출하지 않는다.

- [ ] 6명 모두 완료해야 엔딩이 열리며, 사진·문구·치장 수집 여부를 추가 클리어 조건으로 요구하지 않는다.
- [ ] 중앙 제작진과 좌우 사진·문구가 화면 위에서 아래로 천천히 이동하며 모든 환자의 행복한 후일담이 등장한다.
- [ ] 사진 바로 위 문구는 동일 진행·동일 환자에게 한 플레이어 원문과 일치하고 한 줄로 읽을 수 있다.
- [ ] 환자 대사·다른 실험 발언·LLM 창작 문장을 플레이어의 인용으로 표시하지 않는다.
- [ ] 적절한 원문이 없으면 사진 제목으로 구분 표시하고, 인용 부재로 사진이나 엔딩을 누락하지 않는다.
- [ ] 엔딩 사진을 과거 상담의 실행 사실로 역삽입하지 않고 기록부 사진 칸은 계속 공백으로 유지한다.
- [ ] 건너뛰기·재실행·다시 보기에서 완료·보상이 중복되지 않으며 저장된 사진·문구를 유지한다.
- [ ] 중앙 글·양옆 카드의 겹침, 최소 읽기 시간, 최종 제작진·에셋 표기와 화면 비율별 가독성을 검증한다.

## 15. 현재 구현과 연결 지점

이 절은 Unity 상담실·환자 6명 입장과 임시 대화·기록부·PC·상점·프로필·사진·환경설정 UI, 40종 치장과 블라인드의 실행 중 미리보기, 사용자 설정 저장, 시작 화면 브라우저 시안, 독립 실행하는 서윤 AI 실험의 구현 상태를 기록한다. **Unity UI와 AI는 아직 연결되지 않았다.** 문 클릭 입장과 이름·임시 대사 표시는 로컬 UI 시연이며 정식 해금·임상 설정·상담 완료 판정을 구현한 것이 아니다. AI의 대화·기억·평가·클라이언트 저장은 구현되어 있으나, 최신 총 질문 5개·공감 별도·자동 저장 전용 규칙과 차이가 있다. Unity의 질문 사용량·평가·보상·실제 상품 구매·게임 진행 자동 저장·책·엔딩 연결은 남아 있다. 각 작업의 검증 환경·시점은 별도로 기록한다.

### 문 클릭 환자 입장과 임시 대화 — feature/records

- 사용자 지정 작업 브랜치는 `feature/records`다. 최신 main의 기존 치장·PC·AI 계획을 유지하며 현재 상담실 씬과 독립 프리팹 양쪽에 환자 UI를 추가한다.
- 로컬 시연 순서는 **서윤(`seoyun`) → 도현(`dohyeon`) → 민석(`minseok`) → 태준(`taejun`) → 지은(`jieun`) → 하린(`harin`)**이다. 원본은 `Assets/_Project/Settings/PatientVisits.json`이며 ID·이름·초상화 경로·임시 대사를 담는다. 기존 `Assets/StreamingAssets/GameData/Patients/seoyun.json`의 상담 설정과 분리하고 기존 콘텐츠 버전·평가 항목은 변경하지 않는다.
- 문을 누르면 `Waiting → Entering → Consulting → Leaving → Waiting/Finished`로 진행한다. 입장 요청 직후 상태를 먼저 잠그므로 빠른 연속 클릭도 다음 환자를 예약하지 않는다. 입장·상담·퇴장 중에는 새 입장을 거부한다. 6명 이후에는 `Finished`로 남고 처음으로 돌아가지 않는다.
- 초상화는 문 방향에서 중앙 자리로 이동·나타나며, 책상 윗면 경계의 마스크로 하체를 가린다. 원본 이미지의 어두운 바탕은 `PatientPortrait.shader`와 전용 머티리얼로 표시에서 제거한다. 기록부·PC 클릭 영역과 기존 치장 합성은 유지한다.
- 도착하면 이름과 첫 임시 대사를 자동 표시한다. `계속 듣기`는 타이핑 완료 또는 다음 임시 문장을 표시하며 마지막 문장만으로 상담이 끝나지 않는다. `상담 마치기`로 확인창을 열고 다시 확인해야 퇴장한다. 확인창의 `계속 상담하기` 또는 `Esc`는 종료를 취소한다.
- PC·기록부가 열리거나 닫히는 동안에는 `ConsultationRoomController.IsOverlayBlocking`으로 문·대화 입력을 막는다. 대화창은 숨기고 타이핑과 입퇴장 연출을 일시 정지하며, 창을 닫으면 같은 환자·세션을 이어간다. 상담 상태가 유지된 채 컴포넌트가 비활성화된 경우에도 다시 활성화할 때 같은 환자의 입퇴장을 재개한다.
- 입장할 때 기록부에는 현재 환자 ID·이름·날짜와 미확인 항목을 넣는다. 병력·복약·상담 원문·공개 정보는 임의로 생성하지 않으며 사진 칸도 비운다. 입장 전의 예시 기록과 현재 이름 표시를 실제 환자 설정 연동 완료로 해석하지 않는다.
- `useDemoDialogue=true`가 현재 기본값이다. 후속 LLM 어댑터는 이를 끄고 `PatientArrived(sessionId, patientId)`를 받아 `PresentPatientLine(sessionId, text)`에 결과를 전달한다. 활성 세션과 다른 ID, 종료·퇴장한 세션, 빈 대사는 거부한다. `CompleteConsultation(sessionId)`는 활성 상담을 퇴장 상태로 바꾸는 연결 함수이며 팝업 차단 중에는 거부하므로 닫힌 후 호출한다. 이 함수는 환자 클리어·보상·자동 저장을 의미하지 않는다.
- 이번에는 네트워크 호출, 질문 입력·총 5회 계산, AI 평가, 저장, 승급·엔딩을 추가하지 않는다. 고정 순서는 시연용이며 기존 단계별 해금 기획을 대체하지 않는다. 대화창은 짧은 임시 대사에 맞춘 것으로 긴 LLM 응답의 페이지 나누기·스크롤과 원문 보존은 후속 연결 전에 구현한다.
- 설치는 Edit 모드의 `Gamsamo > Install Patient Visits`, 검사는 새 Play 실행의 빈 상담실에서 `Gamsamo > Run Patient Visit Checks`다. 검사는 실제 UI Raycaster·버튼 이벤트와 상태 전이를 확인하도록 구성하고 `artifacts/ui/patient-visit-checks.txt`에 기록한다. 검사 뒤 Editor 전용 `ResetPreview()`가 입장 수·세션·표시를 초기 상태로 돌린다. 실제 이번 실행 결과와 완료 시각은 17.18절에 확정한다.

### 시작 화면 로컬 시안 — Unity 외부 레이아웃 검토

- 실행: 저장소를 내려받은 뒤 `tools/ui-preview/start-menu/index.html`을 Chrome 또는 Edge에서 연다. `index.html`, `preview.css`, `preview.js`와 상대 경로로 연결된 기존 상담실 이미지·프로젝트 폰트가 함께 있어야 한다.

### 기존 상담실 UI의 완료한 동작

상담실의 왼쪽 아래 클립보드를 누르면 배경이 어두워지고 흐려지며 중앙에 진료기록부가 열린다. 기록부와 내용은 선명하게 유지된다. 닫기 버튼, `Esc`, 기록부 바깥 클릭으로 닫는다. 약 0.2초 동안 투명도와 크기가 전환되며, 닫히는 도중에도 뒤쪽 입력을 막는다. 연속 열기·닫기를 처리하고 닫힌 뒤 원래 버튼으로 키보드 초점을 돌린다.

사용자가 제공한 상담실 이미지와 단독 기록부 이미지를 사용했다. 합성 참고 화면은 에셋으로 추가하지 않았다. 기록부는 외곽과 클립 구멍을 투명하게 처리하고 사진 칸의 인물을 제거했다. 사진 칸은 현재 공백이며 환자 초상화 연결 기능은 없다. 이미지 편집 도구·프롬프트는 [에셋 편집 기록](#asset-edit)에 보관했다.

표 위에 12개 TextMeshPro 필드를 배치했다. 첫 환자 입장 전에는 `MedicalRecordData.CreateSample()`의 가상 예시를 표시한다. 문 클릭으로 환자가 입장하면 현재 ID·이름·날짜와 미확인 항목으로 교체한다. LLM 서버, 환자 원본의 공개 정보·임상 설정, 진행도, 저장과는 아직 연결하지 않았다.

모니터의 PC·상점 UI와 프로필·사진·설정 창을 추가했다. 상점은 원본 카탈로그 40종의 카드와 미리보기·분류별 기본 복원·창문 블라인드 조절을 제공한다. 프로필·사진은 실제 콘텐츠가 없으면 빈 상태를 표시한다. 열기·닫기·탭 동작과 제공 에셋 범위는 8.5절을 따른다. 배경 블러는 하나의 `ConsultationRoomController`가 관리하므로 상점만 닫거나 외형을 바꿀 때도 유지된다.

### 실행과 주요 파일

1. Unity `6000.3.28f1`로 저장소 루트 프로젝트를 연다.
2. `Assets/_Project/Scenes/ConsultationRoom.unity`를 열고 Play를 누른다.
3. 왼쪽 문을 눌러 환자 입장·이름·임시 대사를 확인한다. `계속 듣기`, `상담 마치기`의 취소·확인을 조작하고 퇴장 후 문으로 다음 환자를 받는다. 6명 이후에는 입장이 끝난다.
4. 왼쪽 아래 기록부를 열어 현재 환자 이름·블러를 확인하고 닫기 버튼, 배경 클릭, `Esc`를 확인한다. PC·기록부 열람 중 대화는 보존된다.
5. 오른쪽 모니터 → 상점 → 탭 5개와 각 카드 8개를 확인한다. 카드 선택·분류별 기본 복원·창문 블라인드 3단계를 조작한다. 내부 X·`Esc`는 바탕화면으로 돌아오고 PC X는 상담실로 돌아온다. PC를 닫고 기록부를 열면 선택한 서류철 확대 외형을 확인할 수 있다.
6. 새 Play 실행의 빈 상담실에서 `Gamsamo > Run Patient Visit Checks`를 실행한다. 기존 검사는 `Gamsamo > Run Cosmetic Checks`, `Gamsamo > Run PC UI Smoke Checks`, `Gamsamo > Run UI Smoke Checks`로 각각 실행한다. 서로 다른 검사 메뉴는 동시에 실행하지 않는다.

### 유지해야 할 규칙과 설정

- 환자 방문 컨트롤러는 항상 활성인 상담실 루트에 두고, 초상화·대화창·종료 확인창의 생명주기를 분리한다. 종료 확인창은 대화창 CanvasGroup 밖에 둬 대화 입력 차단에 함께 비활성화되지 않게 한다.
- 문과 환자 UI는 기존 `RoomFrame`의 1920×1080 좌표와 비율을 공유한다. 문 클릭은 UI 버튼 상태뿐 아니라 `TryAdmitNextPatient()`의 상태 검사로도 차단한다. 팝업 닫힘 애니메이션 도중에는 `IsRecordOpen/IsPcOpen` 대신 `IsOverlayBlocking`을 사용한다.
- 방문 세션 ID는 입장마다 새로 생성하고 퇴장 시작 즉시 무효화한다. LLM 응답은 반드시 요청 당시 세션 ID와 함께 전달한다. 이전 환자 응답을 현재 이름 아래에 표시하지 않는다. 임시 대사·초상화 목록을 서버 환자 데이터로 사용하지 않는다.
- `PcDesktopView`는 내부 상점·앱 창 밖의 PC 루트에 둔다. 상점과 앱 창은 아이콘 전용 `shortcuts` CanvasGroup의 자식으로 두지 않는다. PC 닫기 버튼은 내부 창보다 앞에 표시한다.
- PC 에셋의 버튼 좌표는 1520×657, 상점 내부는 1112×534 기준이다. 스케일은 공통 상위 오브젝트에 적용해 표시와 클릭 영역을 함께 움직인다. 원본 합성 화면의 아이콘·상품 카드를 중복 배치하지 않는다.
- 상점 `shopSprites`에는 `templates/`의 빈 배경을 연결한다. `tabs/`의 완성 카드 이미지와 동적 카드 8개를 함께 사용하지 않는다. 카드 좌표는 `CosmeticShop/layout.json`, 하단 안내·복원·블라인드 영역은 y=500~529를 사용한다.
- 원본 카탈로그·블라인드 manifest·PNG는 치장 정의의 기준이다. 상점 레이아웃의 카탈로그 상대 경로는 프로젝트 배치에 맞춰 보정하되 원본 ID·순서·40개 null 가격을 바꾸지 않는다. 원본 통화 KRW를 C로 환산하거나 7.5절의 이전 가격을 새 상품에 임의 적용하지 않는다.

### 구현 우선순위

PC 내부 네 화면, 기본 방 레이어·날씨, 원본 40종의 동적 카드·실행 중 미리보기·창문 블라인드 연결을 구현했다. 치장 통합·회귀 검사 801개 통과는 17.16절 당시 결과다. 문 클릭으로 6명을 차례로 맞이하고 이름·임시 대사를 표시하는 로컬 방문 기능도 추가했으며, 이번 검증 결과는 17.18절에 기록한다. 사용자 설정 저장과 게임 진행 자동 저장은 별개이며 치장 미리보기·임시 방문은 진행 저장을 만들지 않는다. 다음 연결은 실제 환자·대화 API, 프로필·사진 콘텐츠, 음원, 새 40종의 확정 가격·소유·구매 데이터다. 화면 단위는 C이지만 원본 카탈로그 KRW·null 가격은 보존하며 환산 규칙은 없다.

1. **실제 환자 데이터 연결:** 현재 입장 환자의 이름·ID 표시까지 연결했다. 이후 환자 JSON·공개 상태를 `MedicalRecordData`로 변환해 `SetRecord()`에 전달한다. 현재 null·빈 문자열은 `—`로 표시하므로 기획의 미설정·미확인·해당 없음 구분을 추가해야 한다. 방문 시연의 고정 순서·임시 대사를 서윤 확정 설정이나 정식 해금 규칙으로 오인하지 않는다.
2. **대화·진행 연결:** 서버 요청·응답 규격을 확정하고 입력창·응답 대기·오류 재시도·질문 사용량 바를 연결한다. 총 질문 5개 → 마지막 답변·마무리 → 원문 저장 → 두 축 평가 → 보상 정산 → 자동 저장 순서를 적용한다. 책 안내서 열람 중에는 확정 응답을 보존하고 화면 전환은 닫은 뒤 이어간다.
3. **UI 확장 전 프리팹 연결:** 현재 씬과 프리팹의 독립 상태를 정리해 치장·대화 UI 변경의 중복 반영을 방지한다.

**저장·계약:** 저장 형식 2와 자동 저장 전용으로 전환한다. 이전 주제 수를 질문 수로 환산하지 않고 구버전 기록을 보존한다. 클라이언트가 상태·원문 저장을 소유한다. 원문·상태를 같은 revision으로 작성하고 포인터를 마지막에 원자적으로 교체한다. 요청 ID·회차·revision으로 중복 및 늦은 응답을 막고, 저장 실패 시 받은 응답의 저장부터 재시도한다. LLM 공개 후보와 클라이언트 확정 상태를 분리한다.

**평가·기억:** 두 축 각각 70점, 축마다 4항목×25점, 환자 누적 원문·상담자 현재 회차 근거를 유지한다. 최근 약 6왕복과 12,000토큰 요약 기준을 유지하며 원문을 요약으로 대체하지 않는다. 나머지 환자·보상·엔딩·Unity 화면 구현은 이번 AI 작업의 범위가 아니다.

**시연 연결:** OpenAPI·JSON 예제·모의 응답을 먼저 제공하고, FastAPI만 Bearer 인증을 적용한 임시 HTTPS 터널로 연결한다. CLI와 분리된 서버 실행 모드를 제공한다. 주소·키는 로컬 설정이며 공개 문서에 넣지 않는다. 실제 시연 PC·팀원 데모에서 수행한 검사와 서버 측 검사를 구분해 기록한다.

**필수 검증:** 0/1/복합 질문, 4/5 복원, 5/5 마무리 재개, 여섯 번째 질문 차단, 생성·저장 실패, 동일 요청·늦은 응답, 평가 재시도, 재상담·새 실험 분리, 69/70 경계와 정확한 원문 근거. 옛 규칙을 전제로 한 테스트를 새 규칙으로 교체하고 구현·계약·검증 문서를 후속 구현 PR 하나에 함께 제출한다.
