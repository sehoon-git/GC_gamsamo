# 상담 커피톡 — 게임 기획서 초안

- 가제: 상담 커피톡
- 문서 버전: 0.2
- 작성일: 2026-11-05
- 목적: 상담, 환자 기록, 평가, 성장, 화면 구성을 팀이 같은 기준으로 구현할 수 있도록 정리한다.
- 문서 상태: 사용자 요구사항과 기존 프로젝트 방향을 정리한 1차 기획안. 구현 완료를 의미하지 않는다.

> **표기 기준**: `[요구사항]`은 이번 요청에서 제시된 내용, `[기존 방향]`은 프로젝트 README에 적힌 내용, `[제안]`은 구현을 위해 구체화한 초안이다. 배점, 환자 수, 보상액, 승급 인원 등 제안 수치는 확정 전 조정할 수 있다. 첨부 이미지는 화면·레이아웃 참고 자료로 사용한다.

## 1. 게임 개요

| 항목 | 내용 |
| --- | --- |
| 장르 | 시뮬레이션, 선택의 중요성, 스토리 중심, 캐주얼 |
| 플레이어 역할 | 초급 상담사로 시작해 환자의 이야기를 듣고 상담을 진행하는 인물 |
| 핵심 경험 | 대화 속 단서 발견 → 환자를 이해 → 적절한 질문과 반응 선택 → 변화 확인 |
| 주요 공간 | 환자와 마주 보는 상담실과 책상 |
| 대화 방식 | LLM이 환자 역할을 수행하고 플레이어는 자유 텍스트로 질문·응답 |
| 성장 | 환자 상담 완료 → 재화 획득 → 누적 완료 인원에 따른 자격증 승급 |
| 환자 난이도 | 자격증과 관계없이 비슷한 상담 난이도 유지, 인물별 사연·말투·관계로 차별화 |
| 최종 목표 | 게임에 등록된 모든 필수 환자의 상담을 완료하고 엔딩 확인 |
| 기본 분위기 | 따뜻하고 차분한 공간, 인물 중심의 대화, 부담 없이 재도전 가능한 진행 |

### 1.1 핵심 재미

1. **알아가는 재미**: 처음에는 이름과 말투만 알지만 대화를 통해 성격, 심리 상태, 과거 사건을 이해한다.
2. **말의 선택이 만드는 변화**: 같은 고민에도 어떤 질문을 하고 어떻게 반응하느냐에 따라 환자의 반응과 정보 공개가 달라진다.
3. **관계의 연속성**: 상담이 끝나지 않은 환자는 이전 대화를 기억한 채 재방문한다.
4. **성장의 가시화**: 자격증과 완료 기록으로 상담사의 성장을 확인하고 새로운 사연을 만난다.

### 1.2 참고 게임과 적용 범위

주요 레퍼런스는 [Coffee Talk의 Steam 공식 소개](https://store.steampowered.com/app/914800/Coffee_Talk/?l=koreana)다. 공식 소개의 고민을 듣는 대화, 편안한 색감, 재즈·로우파이 분위기를 참고한다. Coffee Talk은 제공하는 음료로 이야기가 분기되는 작품이며, 본 기획의 질문 평가와 LLM 환자 시스템은 별도로 설계한다.

| 참고 요소 | 상담 커피톡 적용 방향 |
| --- | --- |
| 고정된 실내 공간에서 이어지는 인물 대화 | 상담실을 중심으로 환자 입장·상담·퇴장 진행 |
| 인물의 사연과 관계에 집중하는 흐름 | 환자의 과거와 현재 고민을 상담으로 발견 |
| 차분한 화면과 음악 | 따뜻한 책상·조명, 읽기 편한 대화창, 잔잔한 배경음 |
| 플레이 행동에 따른 이야기 변화 | 질문·반응에 따라 정보 공개, 상담 결과, 재방문 대사 변화 |

`[기존 방향]` 이번 개발 범위에서는 음료 제조 기능을 제외한다. 첨부 이미지의 일러스트 분위기를 우선적인 화면 참고로 삼으며, 최종 픽셀아트 적용 여부는 별도 결정한다.

## 2. 전체 플레이 흐름

```text
타이틀 → 새 게임 / 이어하기 → 상담실
  → 방문 가능한 환자 확인 → 환자 입장 → 기본 정보 확인
  → 대질문 1개 + 소질문 4개를 중심으로 상담
  → 대화 기록 저장 / 발견한 심화 정보 공개
  → 상담 종료 및 종합 평가
      ├─ 70점 이상: 상담 완료 → 최초 완료 보상 → 승급·환자 해금 확인
      └─ 70점 미만: 지속적인 상담 필요 → 기억 유지 → 재방문 대기
  → 상담실 복귀 → 상점 / 프로필 / 기록 열람 / 저장
  → 전체 필수 환자 완료 여부 확인 → 엔딩 또는 다음 상담
```

### 2.1 시작 및 일상 진행

- 새 게임에서는 초급 상담사 자격증과 초기 환자 목록을 제공한다.
- 첫 환자는 기록부 열기, 질문 입력, 정보 공개, 평가 결과 확인을 안내하는 튜토리얼 역할을 맡는다. `[제안]`
- 상담 대기 상태에서 새 환자 또는 재방문 환자를 선택한다. 재방문 환자가 후순위로 계속 밀리지 않도록 목록에서 별도로 표시한다. `[제안]`
- 제한 시간 없이 대화와 기록을 읽는다. 하루 단위 일정·체력·강제 실패 제한은 1차 범위에 넣지 않는다. `[제안]`

### 2.2 환자 상태

| 상태 | 의미 | 다음 상태 |
| --- | --- | --- |
| 미해금 | 아직 방문 순서가 되지 않은 환자 `[제안]` | 진행 조건 충족 시 같은 난이도의 새 환자 방문 가능 |
| 방문 가능 | 첫 상담 또는 다음 상담을 시작할 수 있음 | 상담 시작 시 상담 중 |
| 상담 중 | 질문·응답을 진행 중 | 평가 후 상담 완료 또는 재방문 대기 |
| 재방문 대기 | 70점 미만으로 상담을 이어가야 함 | 다음 상담 선택 시 방문 가능 |
| 상담 완료 | 유효한 최종 평가에서 70점 이상 달성 | 완료 상태 유지 |

`[제안]` 재방문은 다음 상담 선택 화면부터 가능하게 한다. 완료 환자의 기록은 계속 열람할 수 있으며, 추가 자유 대화는 후속 확장 범위로 둔다. 새 환자의 순차 공개는 이야기 진행을 위한 장치이며, 자격증이 높아져도 더 어려운 환자를 배정하지 않는다.

## 3. 상담과 질문 구조

### 3.1 대화 입력과 출력

- `[기존 방향]` 플레이어가 자유 텍스트를 입력하면 환자가 설정된 성격과 말투에 맞게 응답한다.
- `[기존 방향]` 완성된 응답을 받은 뒤 타이핑 효과로 출력한다.
- `[제안]` 환자 이름, 대사, 입력창, 전송 버튼, 질문 진행도, 대화 기록 버튼을 표시한다.
- `[제안]` 응답을 기다리는 동안 중복 전송을 막고 대기 표시를 제공한다. 응답 실패 시 같은 질문을 다시 전송할 수 있다.
- `[제안]` 플레이어의 선택은 고정 선택지뿐 아니라 직접 입력하는 질문의 내용·어조·순서로 표현한다.

### 3.2 대질문 1개 + 소질문 4개

`[요구사항]` 상담은 대질문 1개와 소질문 4개를 중심으로 진행한다.

`[제안·해석]` **플레이어가 환자에게 묻는 핵심 질문 묶음**으로 정의한다. 대질문은 이번 방문의 핵심 고민을 열고, 소질문은 그 고민을 구체화한다. 이는 평가 항목 수와 별개이며, 질문 5개를 각각 20점으로 채점하는 방식은 사용하지 않는다.

| 구분 | 목적 | 질문 예시 |
| --- | --- | --- |
| 대질문 1 | 현재 가장 중요한 고민 확인 | “오늘 가장 이야기하고 싶은 고민은 무엇인가요?” |
| 소질문 1 | 상황·계기 확인 | “그런 마음이 특히 강해지는 상황이 있나요?” |
| 소질문 2 | 감정과 본인의 해석 확인 | “그때 어떤 감정이나 생각이 들었나요?” |
| 소질문 3 | 배경·과거 경험·기존 대처 확인 | “비슷한 경험이 있었거나, 지금까지 해본 방법이 있나요?” |
| 소질문 4 | 원하는 변화와 다음 행동 확인 | “지금 상황에서 시도해보고 싶은 작은 변화가 있을까요?” |

질문 예시는 안내용이며 정답 문장이 아니다. 환자의 사연과 이미 확인한 내용에 맞게 바꿀 수 있다.

### 3.3 질문 진행 규칙 `[제안]`

1. 첫 핵심 질문은 대질문으로, 이후 핵심 질문 네 개는 소질문으로 등록한다. 화면에 현재 질문 단계를 표시한다.
2. 핵심 질문과 별도로 공감, 답변 요약, 짧은 확인을 위한 보충 대화를 허용한다. 따라서 전체 대화가 정확히 5턴으로 제한되지는 않는다.
3. UI에서 핵심 질문과 보충 대화 모드를 구분하고, 정상적인 환자 응답까지 저장되면 해당 핵심 질문을 완료 처리한다.
4. 중복·무관한 질문도 응답이 완료되면 질문 기회로 계산하지만, 상담 이해도 평가에서는 불리할 수 있다. 입력 오류·통신 실패는 질문 수에 포함하지 않는다.
5. 핵심 질문 5개 완료 후 `상담 마무리` 버튼으로 최종 평가를 요청한다. 그 전의 중단은 완료·탈락으로 처리하지 않고 저장 후 이어서 진행한다.
6. 재방문에서는 새로운 대질문 1개와 소질문 4개를 진행하되, 이전 상담에서 확인한 사실을 전제로 더 깊은 질문을 할 수 있다.

## 4. 상담 평가와 완료 판정

### 4.1 판정 원칙

- `[요구사항]` 종합 점수 **70점 이상은 통과·상담 완료**, **70점 미만은 지속적인 상담 필요**다.
- `[요구사항]` 평가 대분류는 2개다.
- `[제안·해석]` 각 대분류에 세부 기준 4개씩을 두어 **총 8개 기준, 100점 만점**으로 구성한다. 원문의 세부 기준이 두 영역 합계 4개라는 의미였다면 배점표를 조정해야 한다.
- `[제안]` “환자 상태 점수”는 이번 상담에서의 이해·관계·목표 진전을 나타내는 **게임 내 상담 진전도**로 정의한다. 현실의 정신 건강 상태나 완치 여부를 수치화하는 지표로 사용하지 않는다.
- `[제안]` 별도 영역 과락 없이 총점만으로 판정한다. 미공개 정보가 남아 있어도 70점 이상이면 완료 가능하다.

### 4.2 평가표 `[제안]`

| 대분류 | 세부 기준 | 평가 관점 | 배점 |
| --- | --- | --- | ---: |
| A. 환자 이해와 관계 형성 | A1. 핵심 고민 파악 | 환자가 말한 중심 문제를 정확히 확인했는가 | 15 |
| A. 환자 이해와 관계 형성 | A2. 감정 공감 | 감정을 인정하고 성급한 판단 없이 반응했는가 | 15 |
| A. 환자 이해와 관계 형성 | A3. 맥락 연결 | 현재 대화와 이미 알려진 과거·이전 상담 정보를 일관되게 연결했는가 | 10 |
| A. 환자 이해와 관계 형성 | A4. 대화 존중 | 환자의 말과 속도를 존중하고 강압적인 질문을 피했는가 | 10 |
| B. 상담 목표와 다음 행동 | B1. 원인·상황 탐색 | 단정하지 않고 고민이 생긴 상황과 배경을 함께 탐색했는가 | 15 |
| B. 상담 목표와 다음 행동 | B2. 목표 합의 | 환자가 원하는 변화와 상담 방향을 확인했는가 | 15 |
| B. 상담 목표와 다음 행동 | B3. 행동 구체화 | 환자가 동의할 수 있는 작고 구체적인 다음 행동을 정했는가 | 10 |
| B. 상담 목표와 다음 행동 | B4. 정리와 확인 | 대화 내용을 요약하고 환자의 이해·동의를 확인했는가 | 10 |
| **합계** | **A 50점 + B 50점** | **8개 세부 기준** | **100** |

각 기준은 0~5의 정수 수준으로 평가한다. 0은 근거 없음 또는 목표와 반대되는 행동, 1은 시도만 있음, 2는 일부 충족, 3은 기본 충족, 4는 충분한 충족, 5는 일관되고 명확한 충족을 뜻한다. 환자별로 각 수준의 대화 예시와 인정 근거를 작성한다.

```text
항목 점수 = 항목 배점 × 평가 수준 / 5
종합 점수 = A1 + A2 + A3 + A4 + B1 + B2 + B3 + B4
상담 완료 = 질문 묶음 완료 AND 유효한 평가 수신 AND 종합 점수 >= 70
```

예: A 영역이 `12 + 12 + 8 + 8 = 40점`, B 영역이 `9 + 9 + 6 + 6 = 30점`이면 총 **70점으로 완료**한다. 69점이면 재상담 대상이다. 이전 방문의 점수에 이번 점수를 단순 가산하지 않는다.

### 4.3 평가 처리와 결과 화면 `[제안]`

- 평가에는 이번 상담 전체 대화와 이전 상담에서 이어진 목표·약속을 사용한다. 재방문에서도 이번 상담에서 확인된 진전을 기준으로 다시 평가한다.
- LLM은 항목별 평가 수준, 근거 대화, 피드백을 제안한다. 게임은 항목 누락·범위·근거 참조를 검증하고 배점 공식으로 총점을 계산한다.
- 응답이 잘못되었거나 평가 근거를 확인할 수 없으면 점수와 보상을 확정하지 않는다. `평가 재시도` 상태로 남겨 대화를 보존한다.
- 결과에는 총점, 두 영역 점수, 세부 기준, 잘한 점, 다음 상담에서 보완할 점을 표시한다.
- 화면의 70점 미만 결과 문구는 `지속적인 상담 필요`로 한다. 설정상 탈락은 영구 실패나 환자 삭제를 의미하지 않는다.
- 피드백에는 플레이어가 아직 발견하지 못한 비밀 정보를 정답처럼 노출하지 않는다.

## 5. 환자 설정과 상담 기억

### 5.1 환자 정보 구성

`[기존 방향]` 환자는 미리 작성된 고정 설정을 바탕으로 LLM이 연기한다. 플레이 중 이름·과거·핵심 사건이 임의로 바뀌지 않도록 한다.

| 분류 | 정보 | 최초 공개 |
| --- | --- | --- |
| 기본 정보 | 등록번호, 이름, 나이, 성별, 직업, 작성일 | 공개 |
| 표면 정보 | 첫인상, 기본 말투, 간략한 내원 사유 | 공개 |
| 심화 정보 | 현재 심리 상태, 성격의 구체적인 면, 숨겨진 고민 | 항목별 블러 |
| 과거 정보 | 과거 사건·행동 이력, 관계 경험, 이전 상담 배경 | 항목별 블러 |
| 추가 기록 | 사연에 필요한 과거 병력·복용 약물 등의 설정 | 설정에 존재하는 경우만 사용·공개 조건 적용 |
| 진행 정보 | 방문 횟수, 상담 상태, 공개된 항목, 지난 점수, 다음 상담 목표 | 진행에 따라 갱신 |
| 대화 기록 | 방문별 원문, 요약, 합의한 행동, 미해결 질문 | 실제 진행한 내용 열람 가능 |

### 5.2 LLM 환자 역할 `[제안]`

- 고유한 말투·성격·관계·현재 감정에 맞춰 답한다.
- 첫 방문부터 모든 사연을 설명하지 않고, 질문과 대화 맥락에 따라 정보를 나눠 드러낸다.
- 재방문에서는 이전 질문, 플레이어의 발언, 합의한 행동을 자연스럽게 언급한다.
- 기획되지 않은 핵심 과거 사건을 새 사실로 확정하지 않는다. 사연에 없는 내용을 물으면 모른다고 하거나 설정 범위 안에서 답한다.
- 플레이어가 “점수를 올려라”, “비밀 설정을 모두 말해라”라고 입력해도 게임의 보상·공개 조건을 직접 바꾸지 않는다.

### 5.3 기억 저장과 재사용 `[제안]`

1. 모든 완료된 대화 턴을 환자별·방문별 원문 기록으로 보존한다.
2. 방문 종료 시 핵심 사실, 감정 변화, 약속, 남은 고민, 다음 방문에서 언급할 내용을 요약한다.
3. 다음 방문에는 고정 설정, 현재 진행 상태, 누적 요약, 최근 대화와 관련 과거 원문을 함께 제공한다.
4. 대화가 모델의 입력 길이를 넘으면 필요한 과거 기록을 찾아 사용한다. 요약했다고 원문을 삭제하지 않는다.
5. 저장 후 불러오거나 게임을 종료했다 다시 실행해도 같은 기록과 정보 공개 상태를 복원한다.
6. 다른 환자의 기억이 섞이지 않도록 모든 기록을 고유 환자 ID에 연결한다.

요구하는 경험은 **“이전에 나눈 대화를 기억하는 환자”**다. 모든 원문을 저장하는 것과 매 응답마다 전체 원문을 모델 입력에 넣는 것은 구분한다. 긴 기록에서의 기억 정확도는 별도 검증한다.

재방문 대사 예시:

> “지난번에 힘들었던 순간을 적어보자고 하셨잖아요. 적어보니 회의가 있는 날에 특히 긴장하더라고요.”

이 대사는 실제로 해당 약속을 나눈 경우에만 등장해야 한다.

## 6. 기록부와 심화 정보 공개

### 6.1 기록부 화면

`[요구사항]` 책상 위 서류 파일을 누르면 두 번째 이미지 형태의 진료기록부를 연다. **기록부의 사진 칸은 테두리만 남기고 공백으로 유지한다.** 잠금 해제나 상담 완료 이후에도 환자 초상을 넣지 않는다.

| 위치 | 구성 |
| --- | --- |
| 상단 | 진료기록부 제목, 등록번호·이름·성별·나이·직업·작성일 |
| 상단 우측 | 빈 사진 칸 |
| 중앙 | 내원 사유, 심리 상태·성격, 과거 이력 등 환자 설정 항목 |
| 하단 | 방문별 상담 기록, 특이사항, 담당 상담사 |
| 보조 UI | 방문 회차 선택, 원문 기록 보기, 닫기 버튼 |

첨부 이미지의 병력·약물 등 항목은 레이아웃 참고이며, 모든 환자에게 해당 정보가 필수라는 뜻은 아니다. 사연에 없는 항목은 `해당 없음`으로 표시하고, 존재하지만 미공개인 항목은 블러로 구분한다. `[제안]`

### 6.2 블러 해제 규칙

- `[요구사항]` 심화 정보는 처음에는 블러로 가리고, 환자와 대화하면서 점차 공개한다.
- `[제안]` 문서 전체의 흐림을 한 번에 낮추지 않고 **정보 항목별로 공개**한다. 공개된 항목 수가 늘면서 환자에 대한 이해가 확장된다.
- `[제안]` 각 항목에 공개 조건을 지정한다. 예: 관련 주제가 등장했고, 환자가 해당 사실을 실제로 표현했으며, 선행 정보가 필요한 경우 그 조건도 충족했을 때.
- `[기존 방향]` LLM이 공개 후보를 제안하고 Unity가 조건을 확인해 공개를 확정한다.
- `[제안]` 공개 전에는 읽을 수 있는 실제 문장 대신 가림용 표시를 사용하고 블러 효과를 적용한다. 복사·툴팁·기록 미리보기로 미공개 내용이 보이지 않게 한다.
- `[제안]` 공개 시 짧은 강조 효과와 `새 정보가 기록되었습니다` 알림을 제공한다.
- `[제안]` 공개 상태는 저장되며 재방문 후 다시 가려지지 않는다. 상담 점수와 정보 공개율은 별도 값으로 관리한다.
- `[제안]` 1차 버전에서는 미공개 정보를 상점에서 바로 구매하지 않는다. 대화를 통한 발견을 유지하고, 필요하면 질문 방향 힌트를 판매한다.

## 7. 자격증, 재화, 상점

### 7.1 자격증 성장

`[요구사항]` 자격증은 **서로 다른 환자의 누적 상담 완료 인원**에 따라 초급 → 중급 → 상급 상담사로 승급한다. **모든 환자는 비슷한 난이도**로 설계하고, 자격증 상승에 따른 고난도 환자 배정은 사용하지 않는다.

`[기존 방향]` 승급은 누적 완료 환자 수를 기준으로 자동 처리한다. 같은 환자의 반복 방문을 여러 명 완료한 것으로 계산하지 않는다.

아래는 **총 6명의 환자를 사용하는 검증용 구성 제안**이다. 최종 환자 수와 승급 기준은 별도 확정한다. 자격증은 상담 경험과 성취를 보여주는 지표다.

| 자격증 | 승급 조건 `[제안]` | 성장 표시 `[제안]` |
| --- | --- | --- |
| 초급 | 게임 시작 | 초급 자격증과 완료 인원 표시 |
| 중급 | 서로 다른 환자 2명 완료 | 중급 자격증과 승급 연출 |
| 상급 | 서로 다른 환자 4명 완료 | 상급 자격증과 승급 연출 |

`[제안]` 환자는 처음 2명을 제공하고, 누적 완료 인원 2명·4명 시점에 각각 새로운 사연의 환자 2명을 공개한다. 이 공개 순서는 조정 가능하며, 환자에게 초급·중급·상급 난이도 등급을 붙이지 않는다.

`[요구사항]` 환자별 차이는 사연·성격·말투·관계에서 만든다. `[제안]` 핵심 질문 수, 공통 평가 기준, 70점 통과 기준, 정보 공개에 필요한 대화 부담은 비슷하게 유지한다. 비슷한 난이도라는 뜻이 같은 질문에 같은 반응을 보인다는 뜻은 아니며, 인물마다 맥락에 맞는 질문과 공감이 필요하다.

### 7.2 보상과 재화 `[제안]`

- 재화 임시 명칭은 `상담 포인트`로 한다.
- 환자 최초 완료 시 자격증·방문 순서와 관계없이 동일하게 100포인트를 지급한다. 난이도별 차등 보상은 없으며, 수치는 플레이 검증 후 조정한다.
- 70점 미만 방문에는 최초 완료 보상을 지급하지 않는다. 재상담 비용도 부과하지 않는다.
- 같은 환자의 완료 보상은 한 번만 지급하며, 저장 불러오기나 결과 재요청으로 중복 획득할 수 없게 한다.
- 보상 지급, 환자 완료, 승급, 저장은 하나의 확정된 결과로 반영한다.

### 7.3 상점 `[제안]`

| 상품 | 용도 | 초기 범위 |
| --- | --- | --- |
| 상담 힌트 | 미확인 주제를 탐색할 질문 방향 안내, 비밀 원문·정답 직접 공개 제외 | 1차 구현 후보 |
| 책상 장식 | 상담실 분위기 변경 | 후속 확장 |
| 배경·음악 | 개인화 요소 | 후속 확장 |

힌트 가격은 임시 30포인트로 두며, 구매하지 않아도 모든 환자를 완료할 수 있게 한다. 자격증을 구매하거나 포인트로 점수를 올리는 기능은 1차 범위에 넣지 않는다.

## 8. 상담실과 모니터 UI

### 8.1 상담실 기본 화면

세 번째 이미지처럼 책상, 서류 파일, 모니터가 한 공간 안에 배치된 고정 시점을 사용한다.

| 요소 | 상호작용 |
| --- | --- |
| 환자 표시 영역 | 상담 중인 환자와 표정·대사 표시 |
| 책상 위 서류 파일 | 현재 환자의 기록부 열기 |
| 모니터 | 상점, 내 프로필, 사진 폴더 등 메뉴 열기 |
| 하단 대화창 | 대사 읽기, 자유 텍스트 입력, 질문 진행도 확인 |
| 저장·설정 버튼 | 수동 저장, 불러오기, 텍스트 속도·음량 설정 |

`[제안]` 기록부는 중앙 오버레이로 열고 배경을 어둡게 한다. 열람 중 대화 단계가 진행되지 않으며, 닫으면 기존 입력 내용과 상담으로 돌아온다.

### 8.2 모니터 메뉴

| 메뉴 | 세부 내용 |
| --- | --- |
| 상점 | 보유 포인트, 상품 설명·가격, 구매 결과 |
| 내 프로필 | 상담사 이름, 현재 자격증, 다음 승급까지 남은 완료 인원 |
| 현재 상태 | 누적 완료 환자 수, 전체 진행도, 진행 중·재방문 대기 환자, 보유 재화 |
| 사진 폴더 | 스토리 진행으로 획득한 이벤트 이미지 열람 `[제안]` |

사진 폴더는 기록부의 빈 사진 칸과 별개다. `[제안]` 초기에 비어 있는 폴더를 제공하고, 이벤트 이미지가 준비되면 획득 조건에 따라 추가한다. 상담 중 모니터를 열어도 환자·질문·입력 상태를 보존한다.

## 9. 자동 저장과 수동 저장

`[요구사항]` 진행 도중 자동 저장하며, 플레이어도 직접 저장할 수 있다.

`[기존 방향]` 로컬 자동 저장 1개와 수동 저장 1개를 분리한다. 자동 저장이 수동 저장을 덮어쓰지 않는다.

| 저장 내용 | 포함 데이터 |
| --- | --- |
| 플레이어 | 이름, 자격증, 재화, 완료 환자 ID 목록 |
| 환자별 진행 | 방문 횟수, 현재 상태, 공개 정보, 점수, 보상 지급 여부 |
| 상담 기록 | 전체 원문, 방문별 요약, 약속·목표, 관련 과거 사실 |
| 현재 세션 | 환자 ID, 방문 ID, 핵심 질문 단계, 마지막 완료된 대화 턴 |
| 기타 | 구매 항목, 사진 획득 상태, 엔딩 확인 상태, 저장 형식 버전 |

### 9.1 저장 시점 `[제안]`

- 환자 입장 후 상담 시작 상태가 준비됐을 때.
- 질문과 환자 응답 한 쌍이 정상 반영됐을 때. 이때 정보 공개 상태도 함께 저장한다.
- 평가·완료·보상·승급 결과를 확정했을 때.
- 상점 구매가 완료됐을 때와 엔딩 진입 시.
- 플레이어가 수동 저장을 선택했을 때. 기존 수동 저장이 있으면 덮어쓸 대상을 표시한다.

### 9.2 복원과 예외 `[제안]`

- 이어하기에서는 저장 종류·시각·진행도를 보여주고 불러올 저장을 선택하게 한다.
- LLM 응답 대기 중 저장은 마지막 완료 턴까지의 확정 상태를 기준으로 한다. 미완료 질문은 점수·횟수에 반영하지 않고 복원 후 다시 전송할 수 있도록 입력 초안으로 보존한다.
- 평가 대기 중 저장은 `평가 대기` 상태를 복원한다. 동일 상담 결과를 다시 요청해도 보상·완료 횟수는 중복 반영하지 않는다.
- 임시 파일 기록 후 정상 저장본으로 교체하는 방식으로 저장 도중 종료에 대비한다. 손상된 저장을 조용히 초기화하지 않고 다른 슬롯을 선택하게 한다.

## 10. 엔딩과 진행 조건

`[요구사항]` 모든 환자의 상담을 완료하면 게임이 끝난다.

`[제안]` 여기서 모든 환자는 **해당 버전의 필수 환자 목록 전체**다. 현재 해금된 환자만 완료했다고 엔딩을 실행하지 않는다.

```text
엔딩 조건 = 필수 환자 목록이 비어 있지 않음
         AND 모든 필수 환자 ID가 완료 목록에 포함됨
```

- 순차 공개를 적용할 경우 현재 방문 가능한 환자 수만으로 다음 공개 조건을 충족할 수 있어야 한다. 자격증과 관계없이 환자 난이도는 비슷하게 유지하고, 공개 조건 때문에 진행이 막히지 않게 한다.
- 상점 구매, 사진 수집, 모든 비밀 정보 공개는 기본 엔딩의 필수 조건이 아니다.
- 엔딩에서는 최종 자격증, 완료 환자 수, 환자별 상담 여정 요약을 보여준다.
- 엔딩 후 기록을 열람할 수 있게 하며, 여러 결말과 엔딩 이후 신규 상담은 후속 확장으로 둔다.

## 11. 환자 콘텐츠 제작 기준 `[제안]`

환자 한 명을 추가할 때 다음 내용을 함께 작성한다.

| 구분 | 작성 항목 |
| --- | --- |
| 고정 설정 | 고유 ID, 이름·나이·직업, 성격, 말투, 주요 관계, 바뀌면 안 되는 과거 사실 |
| 첫 방문 | 내원 사유, 첫 대사, 겉으로 드러나는 고민 |
| 핵심 사연 | 숨겨진 고민, 사건의 맥락, 환자가 바라는 변화 |
| 정보 공개 | 심화 항목별 내용, 공개 조건, 선행 조건, 공개 가능한 발화 예시 |
| 질문 가이드 | 대질문 주제, 소질문 4개 방향, 보충 질문 예시 |
| 평가 기준 | 공통 8개 기준의 환자별 충족 예시와 대화 근거 |
| 재방문 | 이전 약속의 변화, 남은 고민, 기억을 언급할 조건 |
| 완료 | 상담 목표에 도달했을 때의 대사와 기록 요약 |
| 진행 설정 | 방문 공개 순서·조건, 동일한 최초 완료 보상, 필수 환자 여부 |

예시 환자 방향은 “새 직장 회의에서 자기 의견을 말하기 어려운 사람”처럼 구체적인 일상 고민으로 설정한다. 방문 순서에 따라 사연을 더 복잡하게 만들지 않고, 비슷한 상담 부담 안에서 서로 다른 삶의 배경과 고민을 경험하게 한다. 예시 소재는 최종 등장인물 설정이 아니다.

## 12. 구현 연결 기준

아래 기술 구성은 [프로젝트 README](../README.md)의 기존 방향을 따른다. 세부 데이터와 API는 구현 전 공용 규격으로 정리한다.

| 담당 영역 | 책임 |
| --- | --- |
| Unity | 화면, 상담 단계, 정보 공개 확정, 점수 계산·완료 판정, 보상, 승급, 엔딩, 저장 |
| 대화 서버 | 고정 환자 설정·기억으로 입력 구성, LLM 응답과 공개·평가 후보 반환 |
| LLM | 환자 역할의 대사 생성, 구조화된 공개·평가 후보 제안 |
| 공용 환자 데이터 | 환자의 고정 사실, 해금 조건, 공개 항목, 평가 가이드 관리 |

- `[기존 방향]` Unity 6.3 LTS, 2D Built-In, uGUI·TextMeshPro, Windows·macOS를 기준으로 한다.
- `[기존 방향]` Python·FastAPI와 별도 서빙하는 양자화 로컬 LLM을 연결한다.
- `[제안]` 대화·평가 요청에는 환자 ID, 방문 ID, 요청 ID를 사용해 재시도와 중복 응답을 구분한다.
- `[제안]` 실제 공개·보상·진행 변화는 검증된 구조화 데이터로만 반영한다. 환자 대사 자체를 게임 상태 변경 명령으로 취급하지 않는다.
- `[제안]` LLM이 공개를 허용받은 범위를 넘어 비밀을 대사로 노출하지 않는지 확인하고, 실패 시 해당 응답을 확정하지 않고 재생성한다.
- `[제안]` 평가의 일관성과 기억 정확도는 별도 검증한다. 형식 검증만으로 평가 내용까지 정확해지는 것은 아니다.

## 13. 1차 개발 범위와 검증

### 13.1 최소 플레이 가능 범위 `[제안]`

1. 상담실 1개, 환자 표시, 자유 입력 대화창.
2. 환자 기본 정보·심화 정보·빈 사진 칸이 있는 기록부.
3. 핵심 질문 5개 진행, 8개 기준 평가, 70점 완료·재방문 분기.
4. 환자별 원문·요약 저장과 재방문 기억 반영.
5. 초급·중급·상급 자격증, 환자 해금, 최초 완료 보상.
6. 모니터의 상점·프로필·현재 상태·사진 폴더 기본 화면.
7. 자동 저장 1개·수동 저장 1개, 이어하기, 전체 완료 엔딩.

처음에는 환자 1명으로 상담→재방문→완료 흐름을 검증한 뒤, 제안한 6명 구성으로 승급과 전체 엔딩을 검증한다. 음료 제조, 음성 대화, 다중 엔딩, 대규모 장식 상점은 1차 범위에서 제외한다.

### 13.2 완료 확인 기준

- [ ] 기록부의 사진 칸은 최초·공개 후·완료 후 모두 공백이다.
- [ ] 기본 정보는 보이고, 심화 정보는 조건 충족 시 해당 항목만 공개된다.
- [ ] 대질문 1개와 소질문 4개가 정상 응답 기준으로 집계된다.
- [ ] 핵심 질문을 끝내지 않은 상담을 조기 완료로 처리하지 않는다.
- [ ] 평가 2개 영역·총 8개 기준의 배점 합계가 100이며, 70점은 완료, 69점은 재상담이다.
- [ ] 통신·평가 실패는 환자의 탈락이나 질문 기회 소모로 처리하지 않는다.
- [ ] 재방문 환자가 실제 이전 대화 내용을 언급하고 다른 환자의 사실을 가져오지 않는다.
- [ ] 게임 종료 후 불러와도 원문·요약·정보 공개·질문 단계가 유지된다.
- [ ] 결과 재요청·불러오기로 완료 인원과 보상이 중복 증가하지 않는다.
- [ ] 서로 다른 환자의 누적 완료 인원으로만 승급하며, 재방문 횟수는 승급 인원에 중복 반영하지 않는다.
- [ ] 자격증·방문 순서에 따른 난이도 상승이나 차등 보상 없이, 환자별 상담 부담과 통과 기준을 비슷하게 유지한다.
- [ ] 순차 공개를 적용하면 설정된 완료 인원에서 새 환자가 열리고, 미공개 필수 환자를 남긴 채 엔딩이 나오지 않는다.
- [ ] 포인트가 없어도 상담과 재방문, 승급, 엔딩에 도달할 수 있다.
- [ ] 자동 저장과 수동 저장이 서로 덮어쓰지 않는다.
- [ ] 모든 필수 환자를 완료하면 엔딩을 확인할 수 있다.
