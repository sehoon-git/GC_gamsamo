## 변경 내용

- `docs/plan01.md` 7.4~7.5절에 코인과 치장 상점을 추가했다.
- 두 축 평균 × 2를 내림한 금액을 기본 보상 기준으로 하며, 환자별 이전 최고 지급 기준보다 오른 차액만 추가 지급한다. 두 축 각각 70점 이상 최초 클리어 시 100C를 1회 추가 지급한다.
- 최초 70/70은 240C, 100/100은 300C. 90/60은 미클리어지만 기본 150C를 지급한다.
- 100·150·200·300·400·500C의 치장 6종, 합계 1,650C. 환자 6명 보상 상한 1,800C이며 전 상품 수집은 보장되지 않는다.
- 상점 진입·결과 표시·구매·장착·자동 저장·별도 실험 지갑·중복 정산 방지·수용 기준을 연결했다.
- 기존 주질문 5회, 자연 종료 후 저장·평가, 두 축 각각 70점 통과, 자동 저장 전용, 6명·비슷한 난이도 규칙은 유지한다.
- 원격 main의 상담실 UI 작업과 인수인계를 병합·보존했다. README 충돌은 최신 실행 안내와 기획 규칙을 모두 유지해 해결했다. Economy의 빈 자리표시 파일은 복원하여 원격 main 대비 코드·에셋 변경이 없도록 했다.
- 이전 인수인계의 푸시 대기 기록은 과거 상태로 보존했다. 이번 작업 시 원격 main에서 UI 작업을 포함한 `904ad55`를 확인했다.

## 함수·연결 지점과 소유권

이번 작업에서 추가·변경한 실행 함수와 클래스는 없다. 보상·상점은 미구현 기획이다.

- LLM은 평가 항목과 근거를 제안하고 코드는 유효성을 검증한다. Unity가 검증 점수로 금액을 계산·확정한다.
- 향후 Economy 담당은 환자별 최고 기본 보상 기준, 최초 클리어 보너스 지급 여부, 회차별 정산 ID, 잔액, 소유 상품, 슬롯별 장착 상태를 관리한다.
- 최고 기본 보상 기준은 잔액과 다르다. 구매해도 줄어들지 않으며 동일 회차 재평가는 새 수입 기회가 아니다.
- 평가 확정 → 보상·완료 상태 정산 → 자동 저장, 구매 시 잔액·소유권 동시 확정 흐름을 적용한다.
- 기존 `ConsultationRoomController.SetRecord(MedicalRecordData)` 등 기록부 진입점은 변경하지 않았다. 치장 레이어 구현 시 기록부 클릭 영역·블러·텍스트 가독성·빈 사진 칸을 유지한다.
- 현재 배경은 단일 이미지다. 장식 레이어 또는 배경 변형이 필요하며 의자 표시 영역도 정해야 한다.
- 실행 UI는 기존 README의 Unity `6000.3.28f1` 실행 절차를 따른다. 이번 문서 변경으로 상점이 실행되지는 않는다.

## 검증 결과와 제한

- 보상 예시 6개, 60/60 → 80/80 재상담 추가 140C·누적 260C를 검산했다.
- 가격 합계 1,650C, 6명 70/70 수입 1,440C, 90/90 수입 1,680C, 최대 1,800C를 검산했다.
- 문서 변경의 `git diff --check`와 충돌 표식 검사 통과.
- 원격 main 대비 실행 코드·씬·에셋 차이가 없음을 확인했다.
