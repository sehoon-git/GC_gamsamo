# 커밋 전용 작업 규칙 PR

- 요청: `sehoon-git/GC_gamsamo` 저장소에 현재 변경의 풀 리퀘스트 생성.
- 작업 브랜치: `codex/commit-only-handoff`.
- 대상 브랜치: `main`.
- 상태: 문서 검토와 PR 게시 준비. 생성 결과와 완료 시각은 게시 후 이 기록에 추가한다.

## 변경 범위와 유지한 내용

- `166a7f0`의 커밋 전용 작업 규칙과 관련 인수인계를 PR로 제안한다. 매 작업은 구현·검증, docs 기록, 로컬 커밋까지 수행하며 자동 푸시는 금지한다.
- 사용자의 명시적인 PR 요청에는 해당 작업 브랜치 게시가 필요함을 `AGENTS.md`에 구분했다. `main` 직접 푸시와 PR 병합은 수행하지 않는다.
- 상담실 UI와 에셋은 이미 `904ad55`를 통해 `main`에 반영되어 있다. 이번 PR에는 게임 코드·씬·에셋 변경이 없다.
- 최신 원격 `main`의 `3a0b5e2`(기획서 v0.4 및 치장 상점)를 작업 브랜치에 병합했다. `docs/README.md`의 기록 목록 충돌은 양쪽 인수인계를 모두 보존하여 해결했다.
- 이전 기록의 “로컬에만 남긴다”는 당시 상태다. 이번에는 후속 사용자 요청에 따라 그 변경을 PR용 브랜치로 게시한다.

## 사용한 기능과 규칙

- `git fetch`, `git diff`, `git log`: 원격 최신 상태, PR 차이, 변경 이력을 읽는다.
- `git switch -c`, `git merge`, `git commit`: 별도 작업 브랜치 생성, 원격 변경 보존, 충돌 해결과 문서 기록에 사용한다.
- GitHub Desktop의 브랜치 게시 기능: 기존 인증으로 PR 작업 브랜치만 게시한다. 일반 CLI 인증 및 GitHub 앱의 Git 객체 쓰기 API는 이전 작업에서 실패했으므로 이 경로를 사용한다.
- GitHub PR 생성 기능: base=`main`, head=`codex/commit-only-handoff`로 리뷰 가능한 PR을 생성한다.
- 새 실행 함수나 클래스는 없다. 기존 기록부의 `SetRecord`, `OpenRecord`, `CloseRecord` 등은 변경하지 않았다.

## 검증과 다음 작업

- PR 차이가 문서 파일로 한정되는지 확인하고, 내부 링크·공백·충돌 표식을 검사한다.
- 게임 코드가 바뀌지 않아 Unity 검증을 재실행하지 않는다. 기존 UI 52개 통과 결과는 이전 구현의 검증 기록이다.
- 다음 작업자는 PR의 작업 규칙과 인수인계를 검토한다. 병합은 별도 요청이 있을 때 수행한다.
- 기능 개발은 최신 `docs/plan01.md`와 환자 표시 데이터·평가 결과 연결 계획을 기준으로 이어간다.
